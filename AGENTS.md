# Meta-Harness project working instructions

Рабочий язык — русский. Сохраняйте цель модульной исследовательской платформы.

- Перед изменениями прочитайте README.md и фактический статус в data/environment_status.json. Проверяйте текущую среду: сохранённый статус — снимок, не гарантия доступности.
- Сохраняйте проверяемую связь вопрос → источник → утверждение → модель → параметры → результат → ограничения. Согласие нескольких агентов не является независимой научной репликацией.
- Делегируйте независимые исследования, реализацию и проверку; не допускайте одновременной записи в один файл.
- Различайте reviewed, installed, tested, validated. Не называйте правила автономными LLM-агентами, CPU-симуляцию QPU, эвристику биологическим прогнозом, процесс полноценной песочницей.
- Держите core без обязательных внешних зависимостей. Тяжёлые научные пакеты запускайте в отдельных окружениях; не устанавливайте их все вместе.
- Проверяйте плагины по закреплённым хешам, ограничивайте ресурсы и входы. Не отключайте контроль доступа ради демонстрации запуска.
- Не генерируйте назначения или операционные инструкции изменения человеческого организма. Абстрактное моделирование должно явно указывать область применимости и отсутствие клинической валидации.
- Проверяйте только реальные риски изменений; обязательные проверки: python -m unittest discover -s tests -v и CLI doctor.
- Секреты задаются через поддерживаемый менеджер секретов или переменные среды на стороне сервера. Не сохраняйте их в коде, снимках, браузерном JS или отчётах.
- Сохраняйте контрольную версию перед длинным этапом. В hosted Work временные каталоги не являются постоянным хранилищем; используйте Library skill либо уже подключённый целевой репозиторий.
- Пользовательские разрешения из текущего диалога имеют приоритет; этот файл не добавляет новых согласований. Внешняя публикация и выдача доступа должны соответствовать конкретному поручению.
