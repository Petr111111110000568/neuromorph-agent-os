# Ограничение обхода каталогов в scan_models()

Исправление BW-PR25-REVIEW-001 для staging PR #25, 17.10.2026.

`scan_models(roots, max_files=5000, max_depth=5, max_matches=250, *, max_dirs=1000)`
имеет общий для всех корней бюджет каталогов. Корневой каталог также учитывается.
`visited_dirs` — число каталогов, успешно перечисленных и возвращённых `os.walk`.
Повторно указанный уже обработанный корень не учитывается ещё раз.

При достижении `max_dirs` обход останавливается до запроса следующего элемента
генератора и возвращает `truncated=True`. Флаг консервативный: он устанавливается
и при точном совпадении размера дерева с бюджетом. При `max_dirs=0` каталоги
не перечисляются; для пустого списка корней `truncated=False`.
Отрицательные, дробные, строковые значения и bool отклоняются с ValueError.

Прежние ограничения по файлам, глубине, совпадениям, пропуску каталогов и
символических ссылок сохранены. Найденный файл не объявляется загруженной моделью.

## Проверка

```sh
python3 -m unittest discover -s integrations/blackwall_openkylin/tests -v
```

Регрессия создаёт 1200 пустых дочерних каталогов: прежний код открывает 1201
каталог при `max_files=1`; исправленный — 1000 и выставляет `truncated=True`.
Используются реальные временные каталоги и наблюдение за настоящим `os.scandir`.

## Границы исправления

Бюджет относится к успешно перечисленным каталогам, а не ко всем системным вызовам.
`os.walk` читает записи одного каталога до yield; ширина отдельного каталога,
попытки открытия недоступных каталогов, число входных корней, задержки stat и
гонки файловой системы этим изменением не ограничиваются. Для полного ограничения
работы нужен отдельный бюджет записей/попыток и потоковый обход. Существующая
семантика счётчика `examined` не изменена. Это исправление конкретного дефекта
пустого широкого дерева, не полная файловая песочница и не приёмка всего BLACKWALL.
