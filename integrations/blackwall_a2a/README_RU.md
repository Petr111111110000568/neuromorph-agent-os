# Blackwall A2A HTTP+JSON bridge 0.1 — экспериментальная совместимость

**Назначение:** отдельный локальный адаптер к уже запущенной Blackwall Swarm v1.5 (openKylin 3.0), использующий несколько объектов и маршрутов **A2A 1.0 HTTP+JSON**. Ядро Meta-Harness, Blackwall, Hermes, существующие SQLite-базы, таймеры и настройки не меняются.

**Не является полной сертифицированной реализацией A2A.** Реализованы Agent Card `GET /.well-known/agent-card.json`, `POST /message:send`, `GET /tasks/{id}`, `GET /tasks`. Не реализованы streaming/SSE, push, реальный multi-turn, federated authentication/OIDC, асинхронный A2A SDK interop и отмена выполняемой операции. Они не заявлены в Agent Card. Взаимодействие с настоящим удалённым узлом отдельно не испытано.

## Почему A2A, а не очередная локальная LLM

Через A2A другие *добровольно подключённые* узлы могут обнаружить возможности агента и запросить фиксированное наблюдение, не получая доступ к shell, GPT-клиенту, файлам или правам ОС. В отличие от MCP, A2A описывает участников и их задачи. Локальный Hermes MCP уже обслуживает инструменты. Это два разных уровня архитектуры.

Официальные первоисточники: [A2A 1.0.1 spec](https://a2a-protocol.org/v1.0.1/specification/), [What's new v1](https://a2a-protocol.org/latest/whats-new-v1/), [MCP 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/).

## Проверка без установки служб

В корне репозитория:

```bash
python3 -m unittest discover -s tests -p test_blackwall_a2a_bridge.py -v
python3 -m workbench doctor
```

Все интеграционные тесты bridge работают на временном каталоге и двух локальных HTTP-процессах, НЕ требуют Qwen, ChatGPT, Tor, сеть Internet, root, OAuth, системные утилиты. Они проверяют локальный транспорт, два отличных идентификатора узлов, токены, дедупликацию, восстановление и отказ в опасных операциях. **Они не доказывают два разных физических компьютера или совместимость с официальным A2A SDK.**

## Локальный запуск с реальной Blackwall v1.5

Проверить отдельно: `curl http://127.0.0.1:8766/health` и наличие токена `~/blackwall/swarm-core-v1.5/state/api.token`. Операторский токен и транспортный токен — разные значения. Не включать отладочный вывод секретов.

```bash
# Команды только в локальном доверенном терминале openKylin:
export BLACKWALL_A2A_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(48))')"
export BLACKWALL_OPERATOR_TOKEN="$(cat "$HOME/blackwall/swarm-core-v1.5/state/api.token")"

python3 -m integrations.blackwall_a2a.bridge --serve --port 8791
```

В другом терминале того же пользователя с *тем же* `BLACKWALL_A2A_TOKEN`:

```bash
python3 -m integrations.blackwall_a2a.client --port 8791 --command cognition
```

Если существующий backend не запущен, попытка чтения записывается как FAILED, но не объявляется успешной. Данные в `~/blackwall/a2a-bridge/state/bridge.sqlite3` ограничены результатами read-only API.

## Разрешённые сообщения

`status` — GET `http://127.0.0.1:8766/api/system`, `audit` — GET `/api/audit/verify`, `cognition` — GET `/api/cognition/manifest`, `plan 4 2` — GET `/api/cognition/plan?x=4&y=2`. Формат `plan X Y`, где обе координаты от 0 до 4. Это лишь *preview* маршрута симулятора, никакого управления устройствами или активации миссий.

Все другие команды, URL, произвольные промпты, файлы, shell, скрипты, вызовы браузера и изменения полномочий отвергаются (HTTP 422). JSON тело ограничено 4096 байт; отклик backend — 90 КБ; повтор `messageId` идемпотентен, другая команда с тем же ID — HTTP 409. При перезапуске `SUBMITTED` переводится в `FAILED`, автоматического повтора и запуска фоновых задач нет. JSON-записи проверяются связанной SHA-256 цепочкой, но **без криптографической подписи доверенным ключом** — хеши не доказывают, что результат истинный.

## Модель угроз и внешний доступ

Порт всегда привязан **только к 127.0.0.1**, по умолчанию 8791. Не перенаправляйте его в Интернет. Без TLS/mTLS, изоляции учётных записей, проверки личности и ролей клиентов такой сервер **не готов к работе через другую машину**. HTTP Bearer рассчитан только на доверенный loopback-контур; другой процесс с доступом к тому же пользователю может получить токен из переменных окружения. Для полноценной федерации нужен отдельный реверс-прокси с аутентификацией, TLS и прикреплёнными к ресурсу полномочиями. Отдельную внешнюю интеграцию нужно проверять с настоящим вторым компьютером.

Репозиторий является публичным: не коммитьте токены, SQLite, локальную память, закрытые файлы, веса моделей, данные пользователей. Действующий Blackwall на ПК не меняется и не перезапускается.
