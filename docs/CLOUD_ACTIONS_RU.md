# Конечный cloud-review через GitHub Actions

Workflow `Bounded public cloud review` (`.github/workflows/cloud-review.yml`) работает на стандартном Ubuntu GitHub-hosted runner в этом публичном репозитории, независимо от открытого Codex и компьютера пользователя. Только публичный discovery с `provider=none`, затем не более одного уже наступившего `cloud_review --once`. Модельный текст сохраняется как непроверенные данные и никогда не исполняется, не коммитится и не применяется к проекту.

Окно жёстко закреплено: **25 сентября 2026 18:30 UTC — 2 октября 2026 18:30 UTC**. События расписания приходят в 00:41, 06:41, 12:41, 18:41 UTC; фактический старт GitHub может задерживать. Между model attempts не менее 6 часов, после 429, provider_unavailable или transport_unavailable — минимум 24 часа. Это верхний предел 28 попыток, не обещание 28 успешных ответов. `github.run_number <= 28` ограничивает также число runner jobs; неуспехи, пустые проверки и ручные запуски расходуют этот консервативный бюджет. Повторные `Re-run jobs` запрещены. После лимита workflow events получают skip без нового runner.

25.09.2026 владелец проверил в UI бюджета аккаунта: **Actions budget $0, Stop usage Yes**. Это записано в `config/cloud_review_schedule.json`: `zero_budget_confirmed:true`, проверенная дата и признаки бюджета; приватные URL аккаунта и платёжные данные не сохраняются. Код не меняет настройки платежей. GitHub документирует бесплатные стандартные runners публичных репозиториев, но artifact storage имеет общую квоту аккаунта; zero-budget stop должен оставаться включённым. Если квота закончится и upload не удастся, цепочка остановится, а не переключится на платный режим. [Официальная информация о биллинге](https://docs.github.com/en/billing/concepts/product-billing/github-actions).

Для запуска: после успешного CI и merge проверенного commit в default branch откройте Actions → Bounded public cloud review → Run workflow на default branch. Внешние API-ключи, PAT, repository secrets, Drive, облачные VM и установки пакетов не нужны. Если перед merge наступит cron после публикации этого workflow, он также может выполнить первый разрешённый запуск. Остановить раньше можно через Disable workflow; изменение подтверждения бюджета на false также запрещает новые запросы. Локальные исполнения для активации не нужны.

Checkpoint восстанавливается только из точного предыдущего активного run **этого workflow/default branch/commit**, выбранного через официальный GitHub Actions API. `actions/download-artifact` получает точные `artifact-id`, `run-id`, repository. Разрешения токена — только `contents:read`, `actions:read`; токен доступен лишь проверке GitHub и скачиванию. Discovery/model subprocesses получают очищенное окружение. Два concurrent jobs не выполняются: `concurrency`, `cancel-in-progress:false`. Job ограничен 8 минутами; model subprocess — 125 секундами с завершением его process group.

Артефакт содержит только checkpoint, cloud state и последний небольшой непроверенный отчёт, суммарно до **128 KiB**, retention **8 дней**. Нет cache, записи state-ветки, полного workspace, сырых stderr, приватных файлов или накопленного архива. За 28 jobs добавляется не более 3.5 MiB до сжатия. GitHub run number — независимый сохраняемый счётчик: потеря артефакта не обнуляет бюджет. Отсутствующий/истёкший/повреждённый checkpoint, потерянная история run, изменение активного commit или contract/auth error останавливают цепочку. Два явно временных статуса provider_unavailable/transport_unavailable допускают следующую попытку только через 24 часа; потраченная попытка сохраняется атомарно до upload. В текущем run повтора нет, общий предел 28 и expiry не расширяются. Только прошлый commit с доказанным `zero_budget_confirmed:false` может быть пропущен до первой активации. После аварийного отменённого job может потребоваться ручной разбор; автоматического reset/retry нет.

Для другой версии кода или нового окна требуется отдельное проверенное изменение. Не удаляйте историю workflow/артефакты ради сброса лимита и не меняйте идентичность модели в текущем job. Расписание cron не имеет поля года; абсолютный expiry проверяется до API/model work, а защита run number прекращает новые runner jobs после 28 событий.

Реализация и тесты подготовлены статически; локальные tests/model/API-запуски не выполнялись по требованию пользователя. Проверить в GitHub CI: `tests/test_cloud_actions.py` плюс полный suite. API и артефакты: [workflow runs](https://docs.github.com/en/rest/actions/workflow-runs), [Actions artifacts](https://docs.github.com/en/rest/actions/artifacts).
