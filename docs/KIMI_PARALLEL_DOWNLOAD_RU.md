# Ограниченная параллельная загрузка весов Kimi

Задание `KIMI-DOWNLOAD-SPEED-001`, база `789471817654ebcdd1d05f461bcdc492573ed128`.
Пользователь разрешил загрузку закреплённого checkpoint на диск D и попросил ускорить её.

`scripts/download_kimi_weights.py --workers 2` загружает разные shards параллельно в одном процессе. Допустимо от одного до четырёх workers. Единственный OS-lock защищает весь каталог; для каждого shard используется отдельный append-only `.part` и собственный HTTP opener. Общая запись состояния синхронизирована.

Сначала загружаются недостающие части. Уже готовые файлы повторно проверяются после сетевой фазы, перед итоговым `complete`. Наличие final-файла или имени в историческом `verified` не заменяет SHA256. Текущая повторная проверка отражается отдельно в `verified_this_run`. Контрольный manifest, SHA256, проверка HTTP 206 и точного Content-Range, TLS/host allowlist, резерв места 120 GiB и ограничения повторов сохраняются.

Ответ HTTP 429 или Retry-After на ошибке закрывает общий допуск новых запросов до сохранённого срока. Срок переживает перезапуск. Уже принятый сервером поток не является новым запросом. Терминальная ошибка останавливает остальные workers кооперативно; сохранённые префиксы не удаляются. Сетевое ожидание ограничено существующим timeout.

Пример контрслучая: первый worker получает 429, второй хочет начать следующий Range другого shard. Второй не должен отправить запрос раньше общего срока, в том числе после перезапуска. Другой контрслучай: один worker проверяет свободное место одновременно с `.part` → final у коллеги; операции должны быть согласованы.

Изменение не устанавливает модельный движок и не запускает инференс. Ускорение проверяется по приросту байтов файлов за измеренный интервал, а не по числу потоков. Предельная скорость зависит от линии, сервера и диска; 100 Мбит/с соответствует теоретическим 12,5 МБ/с до накладных расходов.

Облачные проверки используют маленькие синтетические потоки, без скачивания весов, внешних запросов и model calls. Требуются прежние проверки downloader и новые тесты конкурентной работы на Windows, Linux и macOS.

Официальная справка Hugging Face описывает конкурентную загрузку файлов: https://huggingface.co/docs/huggingface_hub/en/guides/download . Смена загрузчика на отдельный `hf download` во время существующей загрузки не выполняется: его cache/lock не совпадают с этим журналом.
