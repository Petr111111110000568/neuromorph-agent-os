# Допуск публичного брифа перед передачей модели

Предыдущая проверка `source_sha256` показывала лишь, что текст `review` соответствует хешу в том же брифе. Отправитель, способный заменить текст и пересчитать собственный хеш, ещё не предъявляет доказательство принятого оператором пакета. Самостоятельный `provenance_verifier` раньше вызывался только из тестов.

Теперь `continuous.perform` использует его перед включением внешнего брифа в фактический prompt. Проверяется канонический UTF8 JSON всего валидированного пакета (отсортированные ключи, компактные разделители, без ASCII-экранирования), включая review, next_question и метаданные. Отдельный source_sha256 по-прежнему относится к тексту review. Ни один из этих хешей не является отпечатком исходного приватного чата или доказательством научной истины. Данные и разрешение их передать находятся в двух разных фиксированных файлах принятого checkout:

- `config/council_brief.json`: ограниченный публичный пакет, task ID, заявленные URI/время, хеш и вопрос. Он остаётся `unverified`.
- `config/council_brief_admission.json`: отдельно заданные оператором policy и registry, ожидаемый digest канонического пакета, scope, timestamp, срок действия, уровень допуска и отзыв. Runtime не создаёт и не обновляет этот реестр из проверяемого текста.

Scope фиксирован для `neuromorph-agent-os` / `public-council-handoff`. Trust 1 означает только «оператор разрешил передать это непроверенное публичное резюме», а не достоверность источника, личности автора или результата исследования. Сейчас допущен пакет DEEPSEEK-009 с источником `urn:neuromorph:council:DEEPSEEK-009`, timestamp `2026-09-25T21:14:20Z` и сроком до `2026-10-02T00:00:00Z` исключительно.

При отсутствующем, просроченном, отозванном или неподходящем допуске текст не передаётся модели. Общий исследовательский ход может продолжаться без этого брифа в прежнем бюджете. Квитанция допуска использует фиксированные статусы и причины; она не копирует отвергнутый текст. Повреждённый пакет не становится доверенным от добавления поля `trust` или пересчитанного собственного SHA.

Квитанция записывается в минимальный `result.json` сразу после допуска, до сборки prompt. После успешной сборки сохраняются также точный prompt и его SHA256, ещё до единственного обращения к провайдеру. Если сборка или адаптер выбросит исключение, существующий `finalize` сохраняет `no_result` вместе с уже полученной квитанцией и прежними счётчиками. Значение `accepted` подтверждает допуск пакета, а не успешную отправку или ответ модели. Новых повторов это не создаёт.

Гарантия такого checkpoint ограничена сохранным файловым пространством runner и выполнением `finalize`. Потеря всей машины, отмена до записи либо сбой самого хранилища не превращаются в доказанный облачный receipt. Durable reserve попытки продолжает действовать отдельно и не сбрасывает бюджет.

## Граница доверия

Корень доверия — принятое оператором содержимое GitHub checkout и уже имеющийся контроль записи в репозиторий. Хеш commit не удостоверяет автора сам по себе. Изменивший одновременно код, policy и registry в принятой ветке находится за этой границей защиты. Доказательство подписи реестра, защищённость main и отдельная аутентификация его издателя не заявляются.

Это проверка снимка на момент checkout. Отзыв, опубликованный после создания снимка, не становится видимым уже начатому ходу мгновенно; следующий checkout читает новую конфигурацию. Распределённый счётчик отзыва, обновляемый реестр и гарантия отсутствия устаревшего кэша пока не реализованы. Перепредъявление тех же bytes в действующем разрешённом scope допустимо.

Новых HTTP endpoints, пользовательской аутентификации, прав GitHub, внешних хранилищ, ключей или автоматической установки плагинов это изменение не добавляет. Квоты, резерв попытки, предел prompt и общий размер checkpoint сохраняются. Допуск брифа не разрешает выполнять предложенный моделью код.

## Проверяемая приёмка

Облачные тесты должны подтверждать не только ответ pure function, но и фактический prompt mock-провайдера: принятую запись он получает; заменённый текст с пересчитанным собственным SHA, изменённый только next_question, expired/revoked или отсутствующим admission — не получает. Старый ledger должен читаться без сброса счётчиков. Тестовые часы фиксируются; реальный runner использует свой UTC clock.

Проверки выполняются в GitHub Actions без provider credentials. Их фактические квитанции, точный commit и результат сохраняются в PR; этот документ не заменяет состоявшийся запуск.
