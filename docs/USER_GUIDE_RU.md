# Как работать с исследовательским сообществом Meta-Harness 0.6

## Установка и сохранение работы

Распакуйте архив, установите Python3.11+ и запустите `start.cmd` в Windows либо `sh start.sh` в Linux/macOS. Откройте `http://127.0.0.1:8765/society.html`. Ядро использует стандартную библиотеку Python, SQLite и обычный браузер.

Стартовая команда запускает два отдельных процесса workers, транспорт заданий и фоновый координатор. Вкладку можно закрыть; задания продолжат выполняться, пока запущен процесс программы. После Ctrl+C работа остановится, а состояние останется в `state/`. Для резервного копирования остановите программу и сохраните весь каталог `state/` в защищённое место; не копируйте только один SQLite-файл во время записи WAL. Кнопка экспорта выдаёт переносимый JSON исследования, но не полную резервную копию очереди и не механизм импорта.

Приложение в архиве не является круглосуточно опубликованным сайтом. Для постоянной работы нужен собственный включённый компьютер или сервер. Оно не получает API-кредиты, платные подписки и доступы автоматически из аккаунта ChatGPT.

## 1. Сформулировать вопрос

В разделе «Миссии» укажите исследовательский вопрос. Например:

> Сопоставить вычислительные модели клеточного состояния: какие открытые данные позволяют проверить переносимость результатов между наборами?

Выберите класс данных. Для публичного вопроса можно включить online; для внутренних и чувствительных геномных данных текущая версия разрешает только локальную обработку. Не вставляйте персональные последовательности, медицинские записи или секреты в поле вопроса. Это поле используется для поиска, а не для загрузки исследовательского набора.

«Маршрут» покажет найденные по словам карточки и ограничения доступа. Ранжирование здесь лексическое; это не доказанный рейтинг качества агентов. Для authenticated/private нужно отдельное подключение с правами владельца; Tor-транспорт обозначен неподдерживаемым.

«Запустить миссию» ставит три задания: поиск библиографических метаданных, триаж аннотаций и методический контроль. Размер выборки ограничен1–8 источниками. По умолчанию всё работает с локальным каталогом. Поисковый запрос, сформированный правилами из вопроса, сохраняется в журнале — его можно проверить.

## 2. Посмотреть результат

Карточка миссии показывает очередь, работников, события, источники и расчёт. `completed` означает, что три задания завершились и их результат прошёл структурную проверку. `partial` обозначает частичный результат или ошибку провайдера; `failed` — отсутствие принятых результатов. Пустая выдача также может быть корректным ответом поиска и не подтверждает отсутствие явления в природе.

Для аннотации сохраняются источник, DOI/URL, время, SHA-256 очищенного текста, короткий фрагмент и совпадения ключевых слов. Метки `human`, `animal`, `in_vitro` и подобные означают только встреченные слова. Фраза «no human data» может дать одновременно `human` и `negation_present`; это не классификация исследования.

Методический контроль ML работает на синтетических данных. Квантовый контроль — CPU-симуляция маленькой схемы. Ни один из них не предсказывает итоговые признаки взрослого организма и не доказывает квантового преимущества.

В provenance workers передают хеши входа, результата и закреплённого кода. Координатор проверяет согласованность; это не удалённая аппаратная аттестация и не защита от полностью злонамеренного администратора worker.

## 3. Найти реальных внешних агентов, модели и данные

Откройте «Живые каталоги». Выберите провайдера, запрос и лимит. Примеры:

| Провайдер | Запрос | Что получите |
|---|---|---|
| Agentverse | `research` | Карточки предлагаемых агентских сервисов и заявленные возможности |
| Hugging Face models | `scGPT` | Метаданные подходящих репозиториев моделей |
| Hugging Face datasets | `ScienceAgentBench` | Карточки наборов и оценочных задач |

Включённый online выполняет реальный ограниченный запрос к публичному API. Offline ищет в поставляемом реестре; он не имитирует живую выдачу выбранного сервиса.

Статус `directory_listed_not_connected` означает именно найденную карточку. Веса, код и файлы набора не скачиваются; advertised endpoint агента не вызывается. Поля владельца, лицензии и возможностей могут быть заявлены самим автором. Неавторская копия модели не получает доверия оригинального проекта автоматически.

Путь дальнейшего подключения: проверить автора и права → зафиксировать протокол и версию → определить разрешённые данные и бюджет → выполнить небольшое эталонное задание → проверить артефакт независимо → включить конкретную способность. Для платных сетей потребуется собственная авторизация и, возможно, кошелёк/кредиты; эта версия платежи не выполняет.

## 4. Вести журнал утверждений

Выберите завершённую миссию, сформулируйте утверждение и его область применимости, перечислите IDs источников. Для оценки «поддержано в этой области», «опровергнуто» или «недостаточно данных» нужны источники и обоснование. Неизвестные IDs отвергаются.

Оценка записывается как мнение локального пользователя. Она не становится независимой научной валидацией из-за нажатия кнопки. Утверждение без проверки можно сохранить как `unreviewed`, чтобы вернуться к нему позже.

## 5. Создать инспектируемую копию открытого кода

В «Исходниках» укажите `owner/repository`, точный40-символьный commit и SPDX-лицензию. Принимается ограниченный набор стандартных лицензий; полный текст проверяется консервативно. ZIP ограничен10MiB, распакованный размер40MiB, до1000 элементов; ссылки, опасные пути, шифрованные и чрезмерно сжатые архивы отклоняются.

Результат — сохранённые исходники, LICENSE/NOTICE, хеши и запись инспекции. Никакого `pip install`, импорта или запуска полученного кода не выполняется. Успех этой операции не означает установленный агент или право на любые внешние модели и данные из его зависимостей.

В `vendor/sources/` находятся фактически проверенные снимки, перечисленные в `vendor/sources/PROVENANCE.json`. У них сохранены исходные уведомления; см. ограничения рядом с каждым снимком. Инспекция не заменяет анализ всех прав и зависимостей перед промышленным развёртыванием.

## 6. Подключить собственные вычислительные узлы

`local-network` предназначен для одной машины. Для нескольких машин используется `hub`, проверяемый HTTPS и отдельные workers. Команды и требования перечислены в `NETWORK_DEPLOY_RU.md`. SQLite остаётся на локальном диске координатора, не на общей сетевой папке. Workers используют capabilities `discovery`, `evidence`, `simulation`, `directory`; произвольные команды от клиента не принимаются.

В текущем протоколе общий секрет даёт доступ участникам одной доверенной группы. Для независимых организаций нужны индивидуальные удостоверения, scopes, отказ в доступе по умолчанию и отдельный A2A-шлюз; это следующий этап, не выполненное свойство релиза.

## 7. Управление через AI-клиент

`python -m workbench mcp` предоставляет ограниченный stdio MCP-интерфейс с явно закреплённой версией2025-11-25. Подходящий локальный host может вызывать `list_research_agents`, `route_research`, `start_research_mission`, `search_agent_directory`, `society_status`, `record_research_claim` и другие инструменты. Чтобы задания выполнялись, очередь и workers должны работать с тем же `--data-dir`.

Пример запуска: в первом терминале `python -m workbench --data-dir ./state local-network`; в настройке совместимого локального MCP-host команда `python`, аргументы `-m workbench --data-dir /полный/путь/state mcp`, рабочий каталог — распакованный проект. Точные настройки зависят от клиента. Приложение не заявляет совместимость со всеми версиями MCP или непосредственное подключение stdio к веб-ChatGPT. Для веб-клиента потребуется отдельно реализованный и проверенный удалённый транспорт.

Такой AI-клиент может помочь с формулировкой вопроса и объяснением результатов. Все программные лимиты, права и различия между источником, прогнозом и экспериментом сохраняются.
