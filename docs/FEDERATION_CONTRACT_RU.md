# Контракт исследовательской федерации Meta-Harness 0.7.0

Дата: 24 сентября 2026 года. Документ описывает реализованный собственный протокол `meta-harness-contribution/1` и текущие ограничения. Распознавание карточки A2A не означает реализации A2A RPC. MCP stdio ядра представляет отдельный ограниченный интерфейс из 24 инструментов версии `2025-11-25`.

## 1. Участники и границы доверия

| Сторона | Возможности | Подтверждённая идентичность |
|---|---|---|
| Локальный оператор | Создание задач и сводок, приглашения, приёмка, отмена и отзыв | Доверие к локальной учётной записи ОС и консоли |
| Кандидат из каталога | Метаданные о возможностях и происхождении | Заявления издателя; организация и компетентность не проверены |
| Присоединившийся исполнитель | Аренда приглашённой задачи, сдача своих результатов, обмен кредитов, чтение выданных сводок | Владение credential; не удостоверение организации |
| Доверенный worker | Задания существующей внутренней очереди | Отдельный механизм доверенной группы; не внешний участник федерации |

Административный HTTP-интерфейс привязан только к `127.0.0.1:8765`. Он не предоставляет отдельной многопользовательской аутентификации: локальные процессы на компьютере оператора считаются доверенными. Его нельзя публиковать наружу через произвольный reverse proxy. Внешний шлюз имеет отдельный набор маршрутов и по умолчанию слушает `127.0.0.1:8767`.

## 2. Обнаружение и предложение

Поиск принимает `query`, `providers`, `limit`, `online`, `data_class`. Реализованы `agentverse`, `huggingface_models`, `huggingface_datasets`, `mcp_registry`; лимит составляет 1–8 записей на каталог. Online допускает только публичный поисковый вопрос. Локальный режим отмечает `retrieval_kind=bundled_registry` и нулевое число сетевых запросов.

Кандидат сохраняет ссылку, тип сущности, заявленные возможности, происхождение, время получения и ограничения. Чтение известной JSON-карточки не вызывает её исполняющий endpoint. Для v3 onion требуется заданный пользователем локальный SOCKS5 proxy; обращения к неопределённым onion-адресам, индексирование всей сети и обход авторизации отсутствуют. Транспортный контракт — в [FEDERATION_DISCOVERY_RU.md](FEDERATION_DISCOVERY_RU.md).

Черновик связывает `candidate_id` и `offer_id`, включает задачу, критерии, вознаграждение и существующие ресурсы для обмена. Сопоставление возможностей лексическое, без независимой проверки компетентности. `delivery_status=draft_not_sent`: создание черновика не отправляет сообщение, не выдаёт токен и не регистрирует участника. Декларация `meta_harness.collaboration.opt_in=true` в карточке не заменяет принятие конкретных условий.

## 3. Фиксированные условия задачи

`create_offer(body)` принимает:

| Поле | Контракт |
|---|---|
| `title`, `description` | Непустой текст, до 200 и 8000 символов |
| `task_type` | `literature_review`, `dataset_qc` или `method_reproduction` |
| `requirements` | 1–30 текстовых критериев приёмки |
| `data_class` | Только `public` |
| `reward_credits` | Целое 0–10 000; за принятый результат |
| `max_assignments` | Целое 1–1000; предел принятых и зарезервированных назначений |
| `lease_seconds` | 10–604 800; по умолчанию 3600 |
| `expires_in_seconds` | 30–2 592 000; по умолчанию 604 800 |

В канонический JSON условий входят задача, критерии, вознаграждение, максимальное число назначений, класс данных, срок аренды, политика ручной проверки и `grant_scopes`. SHA-256 этого JSON — `terms_hash`. Условия существующего предложения не редактируются: изменение требует нового предложения. Абсолютный срок предложения и состояние доступности возвращаются отдельно.

Фиксированные полномочия: `offers:read`, `assignments:claim_invited`, `results:submit_own`, `summaries:redeem`. Членство привязано к одному приглашённому предложению. Баллы не являются деньгами, не переводятся другим участникам и не начисляются за само время работы.

## 4. Приглашение и присоединение

Администратор вызывает `create_invitation({offer_id, expires_in_seconds?})`. Срок приглашения — 10–604 800 секунд, по умолчанию 86 400, с ограничением сроком предложения. Ответ содержит `invitation_id`, `offer_id`, `invite_token`, `terms_hash`, `expires_at`, `single_use=true`.

Пригласительный секрет возвращается только при создании; в SQLite сохраняется его SHA-256. CLI записывает его в новый файл с правами `0600` на POSIX и не печатает в stdout. Повторная запись существующего файла запрещена. Прототип не выполняет доставку файла.

`join` содержит ровно `invite_token`, `terms_hash`, `name`, `capabilities`, `accepted_terms:true`. Срок приглашения проверяется после получения блокировки транзакции. Неверное, использованное или истёкшее приглашение не допускает вступления. Ошибка принятия условий не расходует действующее приглашение.

Ответ содержит `member_id`, одноразово возвращаемый `member_token`, полномочия, баланс и `identity_assurance=admitted_credential_only`. В базе хранится только хеш рабочего токена. Рабочий токен сам по себе срока истечения не имеет; действует до явного отзыва. При потере credential потребуется новый допуск; восстановления исходного токена нет.

## 5. Работа, приёмка и бюджет

Последовательность состояний: `claimed → submitted → accepted/rejected`. Неиспользованная до срока аренда становится `expired`; отмена предложения или отзыв участника переводит ещё не сданную работу в `cancelled`.

- `claim(token,{offer_id,idempotency_key?})` проверяет приглашённое предложение и свободное место. CLI требует явный `--idempotency-key`. Повторный ключ возвращает прежнее назначение; просроченная попытка не получает новую аренду автоматически. Для новой попытки после освобождения места нужен новый ключ.
- `submit(token,{assignment_id,result,source_refs,limitations})` принимает непустой JSON-объект, 1–50 ссылок/идентификаторов источников и 1–30 ограничений. Результат относится только к своему назначению и сдаётся до истечения аренды. Его хеш включает содержимое, источники и ограничения.
- Сданный результат фиксируется. Точный повтор возвращает прежнее состояние; замена отклоняется. Результат доступен автору и локальному проверяющему, автоматически не публикуется.
- `review({assignment_id,decision,rationale})` доступен локальному администратору: `decision` равен `accepted` или `rejected`; обоснование обязательно. Окончательное решение неизменно. Повтор не даёт второго начисления.
- Принятая работа начисляет награду ровно один раз. Новый ключ участника не создаёт дополнительного назначения, пока есть его активное, сданное или уже принятое назначение по предложению.

Бюджет равен `reward_credits × max_assignments`. Арендованные и сданные работы резервируют места. Принятые расходуют бюджет; просроченные, отменённые и отклонённые освобождают резерв. После отмены предложения можно проверить уже сданные результаты по исходным условиям. Конкурентные операции сериализуются SQLite `BEGIN IMMEDIATE` и защищаются уникальными ключами журнала.

Ручная приёмка означает решение по критериям задачи. Она не является доказательством биологической причинности, клинической пригодности или независимой репликацией. Исполнитель не может вызвать приёмку через членский API.

## 6. Разрешённые сводки и выдача доступа

`add_resource(body)` требует `kind=research_summary`, `title`, `summary`, `content`, `license`, `data_class`, `cost_credits`, `rights_confirmed:true`, `redistribution_allowed:true`. Стоимость — целое 0–100 000, текст — до 30 000 символов. Допустимы классы `public` и `internal`: второй означает разрешённую к выдаче участникам сводку, подробные метаданные которой скрыты от публичного каталога.

Права подтверждает локальный оператор. Модуль не проводит юридическую или медицинскую экспертизу текста. Явные длинные последовательности и очевидные форматы FASTA/VCF отклоняются; это не полноценный DLP. Геномы, медицинские сведения и чужие материалы без права передачи не допускаются независимо от указанной метки.

Публичный каталог никогда не возвращает текст ресурса. Для внутреннего ресурса он также скрывает исходное название, описание, лицензионные детали и `content_hash`: хеш короткого вывода способен раскрыть его подбором. Локальный администратор и участник с выданным правом могут получить эти поля.

`redeem(token,{resource_id})` проверяет баланс, списывает стоимость и создаёт отдельное право доступа. Повторный обмен на тот же ресурс не списывает кредиты снова. Даже ресурс с нулевой стоимостью требует явного `redeem`. `access(token,resource_id)` возвращает содержимое только при действующем credential и наличии права. Отзыв членства блокирует дальнейшее чтение; уже полученный текст технически отозвать невозможно.

## 7. Сетевой API

Тела и ответы — JSON. Авторизация: `Authorization: Bearer <member_token>`. Секрет не передаётся в URL. Ошибки: `400` — запрос/состояние, `403` — доступ, `404` — неизвестный маршрут/объект, `413` — размер HTTP-тела, `429` — частота запросов.

| Метод и маршрут шлюза | Доступ | Назначение |
|---|---|---|
| `GET /.well-known/meta-harness.json` | Публичный | Самоописание протокола; `a2a_compliant=false` |
| `GET /v1/offers` | Публичный | Условия и доступность задач |
| `GET /v1/resources` | Публичный | Ограниченные метаданные сводок |
| `POST /v1/join` | Одноразовое приглашение | Принятие условий и выпуск credential |
| `GET /v1/member` | Участник | Собственное членство и баланс |
| `GET /v1/assignments` | Участник | Собственные назначения и результаты |
| `POST /v1/claim` | Участник | Аренда приглашённой задачи |
| `POST /v1/submit` | Участник | Сдача собственного результата |
| `POST /v1/redeem` | Участник | Обмен кредитов на право чтения |
| `GET /v1/access?resource_id=…` | Участник с правом | Чтение сводки |

У шлюза нет маршрутов создания предложений, приглашений, ресурсов, приёмки, экспорта, отмены или отзыва членства. Локальный API: `GET /api/federation` и `GET /api/federation/{offers,resources,candidates,reviews,export}`; `POST /api/federation/{discover,card,offer,resource,review,proposal,cancel,revoke}`. Создание приглашений выполняется через локальный CLI.

Внешняя привязка требует IPv4 literal, TLS-сертификата/ключа и `public_base_url` с HTTPS origin. Проверяются Host и сертификаты; TLS минимум 1.2. Browser-origin запросы участников запрещены: шлюз предназначен для программного клиента. Перенаправления и proxy окружения клиент участников не использует. Лимит считает непосредственный peer и не доверяет `X-Forwarded-For`; обратный proxy требует отдельной продуманной конфигурации.

## 8. Лимиты и хранение

| Ограничение | Значение |
|---|---|
| HTTP-тело шлюза | До 128 KiB; Content-Length, JSON, без Transfer-Encoding |
| Каноническое тело операции обмена | До 64 KiB, конечные JSON-числа |
| Соединения шлюза | До 32 одновременно; TLS handshake до 5 секунд |
| Частота | До 120 запросов за 60 секунд на peer; до 1024 активных peer-счётчиков |
| Socket timeout шлюза | 10 секунд |
| Основные таблицы обмена | До 10 000 записей на ограничиваемую таблицу; журнал ограничен числом начислений и выдач |
| Локальные кандидаты | Последние 1000 записей |
| История поисков и черновиков | По 100 записей |
| Серия `scout` | 1–20 циклов; интервал 10–3600 секунд |

SQLite WAL находится на локальном диске координатора. Перезапуск сохраняет условия, членства, результаты, решения, журнал и права. Физическая многосерверная репликация SQLite не реализована.

Экспорт содержит публичные запросы, метаданные, администраторские черновики и журнал начислений/списаний. Токены, их хеши, тексты результатов и содержимое сводок не включаются. Экспорт — журнал для анализа, не полная резервная копия. Базу с результатами и защищённые credential-файлы хранят отдельно от распространяемой сборки.
