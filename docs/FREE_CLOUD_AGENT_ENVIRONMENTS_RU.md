# Бесплатные облачные среды агентов и IDE

Источники проверены **25.09.2026** по официальным страницам через Exa Search. Статус исследования: `reviewed`; он не означает установленную интеграцию или успешное исполнение проектной задачи. Обновление **26.09.2026**: по проверке основного контроллера приложение Jules уже доступно в Google-аккаунте пользователя; установка GitHub App с доступом только к выбранному репозиторию ожидает подтверждения. Исследование само по себе не создаёт ключи, платёжные обязательства или работающие процессы.

`sources_reviewed: 35` — сумма `numResults` пяти поисковых запросов (5 + 10 + 10 + 5 + 5), то есть 35 поисковых позиций, включая дубликаты, а не 35 независимо прочитанных документов. Значимые утверждения ниже дополнительно проверены загрузкой первичных страниц. Неофициальные обзоры и пользовательские комментарии в issues не использованы как доказательство свойств услуг.

Практический кандидат для следующего подключения — **Jules Free**: по документации модель и отдельная облачная VM включены, есть видимые задачи, расписания и PR. Доступ пользователя к приложению уже подтверждён; доступ к проектному репозиторию, успешная задача и расписание пока не подтверждены. Остаток квоты этого аккаунта не измерен. Бесплатную постоянно включённую VM без квот и сроков жизни это исследование не обнаружило.

Название **Agentic OS / AgentOS / Cognitive OS неоднозначно**. Строки таблицы относятся только к названным репозиториям; они не устанавливают, какой именно продукт имелся в виду ранее. Декларация агента, лицензия на код, вычислительная среда и доступ к модели — четыре разные части подключения.

Доступ к интерфейсу Jules проверен отдельно; это не подтверждает остальные продукты или успешное исполнение задачи. Страна аккаунта ради доступа не изменялась.

## Jules: конкретный вариант подключения

Официальная точка входа — [приложение Jules](https://jules.google.com), указанное в [Getting started](https://jules.google/docs/). Минимальный проверяемый сценарий:

1. Завершить ожидающее подтверждения подключение GitHub App только к публичному проектному репозиторию после просмотра фактических разрешений. Перед запуском проверить доступный бесплатный лимит; уже открытое приложение не доказывает наличие свободных слотов.
2. Запустить одну ограниченную задачу: изучить один модуль, добавить содержательный тест или исследовательскую записку со ссылками, выполнить разрешённые проверки в облачной VM, подготовить PR. Не передавать учётные данные других платформ.
3. Проверить историю, результаты тестов, commit и PR. После успешного пробного результата использовать нативный Scheduled Task, например одну задачу в сутки. Расписание Jules само по себе **не резервирует слоты существующего GitHub ledger**: общий лимит запусков требует явного согласования расписаний/учёта.
4. Результаты обменивать через канонический GitHub и фиксированные артефакты. Авторизация Jules не предоставляет ему сессии Qwen, DeepSeek, ChatGPT или HF. Расписание и автосоздание PR не означают автоматическое слияние в `main`.

Официальный [changelog](https://jules.google/docs/changelog/) от 10.12.2025 прямо сообщает доступность Scheduled Tasks всем пользователям; запись от 26.01.2026 добавляет редактирование, паузу и возобновление. [Страница расписаний](https://jules.google/docs/scheduled-tasks/) ещё содержит старое ограничение «удалить и создать заново». Фактические controls следует проверить в UI. Suggested Tasks — отдельная функция; запись от 10.12.2025 относит её к Pro/Ultra, поэтому она не включена в предложение с бюджетом 0.

Есть и расхождение модели: таблица Plans пишет Gemini 2.5 Pro, но changelog от 30.01.2026 объявляет Gemini 3 Flash базовой моделью всех тарифов; от 09.03.2026 — Gemini 3.1 Pro для Pro. В текущем интерфейсе пользователя основной контроллер наблюдает **Gemini 3.6 Flash**. Это подпись в UI, а не квитанция уже выполненного вызова или гарантия модели для всех Free-аккаунтов. В результате первой задачи следует сохранить доступные фактические сведения о модели и версии.

Для последующей программной интеграции [Jules REST API](https://jules.google/docs/api/reference/) использует отдельный ключ из Settings, до трёх ключей. Сначала требуется подключение GitHub App через web. API alpha поддерживает источники, сессии, сообщения и историю activities; `AUTO_CREATE_PR` включается явно, а планы API-сессий по умолчанию auto-approved. Ключ хранится только в облачном secret store. Наличие API в документации не является проверкой ключа, квоты или доступности этого аккаунта. Для первого нативного расписания отдельный API-ключ не нужен.

## VPN: защищённое подключение, отдельное от runtime

**Proton VPN Free** предлагает одно одновременное устройство, отсутствие лимитов времени и объёма данных, без искусственного ограничения скорости. Реальная пропускная способность не гарантирована. Бесплатный сервер выбирается автоматически; переключение выбирает следующий случайным образом, с cooldown. Это не произвольный выбор страны. [Сравнение тарифов](https://protonvpn.com/free-vpn/free-vs-paid), [правила смены сервера](https://protonvpn.com/support/change-server-free-plan).

**Cloudflare WARP** имеет [бесплатное приложение](https://one.one.one.one/). Режим DNS only шифрует DNS, а Traffic and DNS туннелирует трафик к сети Cloudflare. Документация прямо говорит, что WARP не предоставляет анонимность и не предназначен для имитации другой страны; WARP+ — платная подписка. [Режимы WARP](https://developers.cloudflare.com/warp-client/warp-modes/).

VPN не предоставляет GPU, VM, модельные токены или продолжение задачи после выключения компьютера. Он не меняет допустимость аккаунта, его квоты и договорные условия. В этом исследовании ничего не устанавливалось, сеть не перенастраивалась, аккаунты не переводились между регионами. Для уже исполняемых облачных задач VPN на пользовательском ПК не является механизмом непрерывности.

## Происхождение и границы проверки

Все ссылки выше — первичные страницы разработчиков, дата обращения **2026-09-25**. При конфликтах сохранены обе версии утверждения и указана более свежая датированная запись. API docs Jules доступны по `/docs/api/reference/`; запросы к `/docs/api/` и `/docs/api/overview/` не дали документа и не использованы как доказательство отсутствия API.

Первичный research-проход не проверял аккаунты. Последующее наблюдение контроллера подтверждает только доступ пользователя к приложению Jules и указанную подпись модели; GitHub installation остаётся на шаге подтверждения. Очередь, остаток квоты, первый результат, PR и повторный запуск по расписанию ещё не проверены. Здесь нет доказательства бесконечной работы: даже автономные облачные задачи ограничены тарифами, доступностью сервиса, ошибками и необходимостью сохранять результаты за пределами временной VM. Приложение с видимым чатом и неограниченный бессрочный вычислительный хост — разные свойства.
