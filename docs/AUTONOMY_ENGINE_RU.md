# Ограниченный цикл самостоятельного развития ПО

Модуль `workbench.autonomy` выполняет один конечный цикл: собирает публичные метаданные, составляет план по заданным целям и при явно включённом доступе обращается к одной модели. Результат — проверяемое предложение файлов. Это действующая автоматизация обнаружения и подготовки вклада в разработку; она не превращает найденные ресурсы в согласившихся участников и не воспроизводит самостоятельное научное сообщество.

Ядро использует только стандартную библиотеку Python. Код модели не запускается; рабочее дерево в этом цикле не изменяется. Автоматическое создание ветки и черновика PR, если соответствующий workflow включён и доступен, выполняется отдельным ограниченным publisher после повторной проверки результата. Автоматического слияния нет.

## Запуск

Из корня репозитория:

```sh
python -m workbench.autonomy --config config/autonomy.json --output-dir runtime/autonomy --provider none
```

Это реальный автономный проход по локальному реестру без сетевых обращений. Для чтения четырёх реализованных публичных каталогов:

```sh
python -m workbench.autonomy --config config/autonomy.json --output-dir runtime/autonomy --online --provider none
```

Для одного запроса модели нужны собственный действующий API-ключ, явно разрешённое использование модели и флаг `--online`. В автоматизации GitHub ключ хранится в Actions Secrets; его не следует вставлять в файл конфигурации, командную строку или текст задачи. Поддерживаемые имена секретов: `OPENAI_API_KEY` и `ANTHROPIC_API_KEY`. Разрешение задаётся `AUTONOMY_ALLOW_MODEL_CALLS=true` в окружении либо `allow_model_calls: true` в проверяемой конфигурации.

```sh
python -m workbench.autonomy --config config/autonomy.json --output-dir runtime/autonomy --online --provider auto
```

`auto` выбирает OpenAI, если задан его ключ, иначе Anthropic; при отсутствии обоих возвращает `blocked_provider_missing`. Неверный ключ не вызывает автоматического переключения на другого поставщика. `--provider openai` или `--provider anthropic` задают выбор явно; `--provider none` полностью отключает инференс. Поставщик из CLI имеет приоритет над `provider` конфигурации.

Отказ API, отсутствие ключа или квоты сохраняются как штатный результат цикла, код завершения CLI — 0. Неверная конфигурация и небезопасный путь вывода дают код 2. Это позволяет получать отчёты планировщика, даже когда платная модель недоступна; готовность предложения определяется содержимым JSON, а не одним кодом завершения.

## Входы и пределы

Схема конфигурации версии 1 содержит:

| Поле | Назначение и ограничение |
|---|---|
| `project.name` | Публичное название, до 160 символов |
| `project.repository_url` | HTTPS-адрес репозитория GitHub без учётных данных |
| `project.public_context` | Явно подготовленный публичный контекст, до 10 000 символов |
| `discovery.query` | Публичный поисковый запрос, до 300 символов |
| `discovery.providers` | От одного до четырёх разрешённых каталогов, без повторов |
| `discovery.limit_per_provider` | От 1 до 8 карточек на каталог |
| `development.goals` | От 1 до 8 целей развития ПО, до 1 000 символов каждая |
| `development.max_tasks` | От 1 до 5 задач в предложении |
| `provider` | `auto`, `none`, `openai` или `anthropic` |
| `allow_model_calls` | Явное логическое разрешение; по умолчанию false |
| `providers.openai` / `providers.anthropic` | Идентификатор модели и `max_output_tokens`, от 256 до 6 000 |

Неизвестные поля, дубли ключей JSON, управляющие символы, неконечные числа и слишком глубокие структуры отклоняются. Endpoint нельзя переопределить через конфигурацию или карточку. Секретоподобные строки по известным шаблонам и совпадение с используемыми ключами отклоняются; это дополнительная проверка, а не универсальная система предотвращения утечек. Классификацию `public_context` как публичного задаёт владелец проекта.

Система не сканирует все файлы репозитория или все переменные среды. Модель получает только публичный контекст из конфигурации, цели, метаданные обнаруженных карточек и связь с источниками. Чтение локального реестра делегировано существующему ограниченному модулю каталогов. Пользовательские геномы, частные рабочие файлы, секреты и полный исходный код в контекст модели не включаются.

## Обнаружение и реальное подключение

Используется существующий `workbench.federation.discovery.discover`: Agentverse, Hugging Face Models, Hugging Face Datasets, Official MCP Registry. Максимум — четыре запроса каталогам, до 32 нормализованных карточек за цикл. Agentverse использует поисковый POST; это чтение каталога, а не отправка задания агенту. Остальные адаптеры читают публичные API. Карточки, команды установки, адреса агентов и MCP-инструкции не запускаются. Ошибки каталогов сохраняются в `provider_reports`.

| Факт | Что отражает отчёт |
|---|---|
| Карточка найдена | `status: discovered`; источник и происхождение доступны |
| Запрос модели сделан | `model_requests: 1`; это обращение к API поставщика |
| Ответ модели получен | `model_response_received: 1`; это не научная проверка ответа |
| Файлы прошли проверку схемы | `proposal.status: validated`; содержимое всё ещё требует проверки |
| Самостоятельный внешний агент вступил | Данный модуль это не делает; `enrolled_external_agents: 0` |

Поля `agent_endpoints_contacted: 0` и `enrolled_external_agents: 0` сохраняются независимо от числа карточек и модельных ответов. Карточки моделей, наборов данных и MCP-серверов сами по себе не являются автономными агентами. Существующий протокол федерации допускает отдельное добровольное вступление оператора исполнителя; этот цикл не обходит такой процесс.

## Контракт модельного запроса

Реализованы два фиксированных endpoint:

- OpenAI Responses API: `https://api.openai.com/v1/responses`, `store: false`, без tools; запрашивается JSON object.
- Anthropic Messages API: `https://api.anthropic.com/v1/messages`, версия `2023-06-01`, без tools; строгое JSON-содержимое запрашивается инструкцией и проверяется после ответа.

Имена моделей задаются в конфигурации. Наличие строки модели не подтверждает её доступность на конкретном аккаунте. Адаптер не меняет тариф, не регистрирует аккаунт и не выдаёт себе разрешения. Автоматического повторения запроса и перехода к другой модели при ошибке нет.

За цикл выполняется не более одного обращения к модели; таймаут сетевого запроса — 45 секунд, размер читаемого ответа — не более 192 KiB, выход ограничен токенами конфигурации. Число запросов и размер ответа ограничены, но денежный бюджет в валюте здесь не вычисляется: тариф и стоимость контролируются средствами API-поставщика. Повторный запуск планировщика может сделать новый платный запрос даже для прежних входов.

Транспорт не следует перенаправлениям и не выбирает proxy из окружения. В результаты не включаются заголовки авторизации, произвольные тела ошибок сервера или текст исключений. Основные статусы:

- `disabled`: модель отключена явно.
- `blocked_provider_missing`: подходящего ключа нет.
- `blocked_offline`: ключ есть, но сетевой режим не включён.
- `blocked_model_calls_not_allowed`: нет явного разрешения модельного вызова.
- `access_denied`, `rate_limited`, `request_rejected`, `model_or_endpoint_unavailable`, `provider_unavailable`, `transport_unavailable`: соответствующий класс отказа API.
- `incomplete_response`, `invalid_response`: ответ не завершён или не соответствует транспортному/JSON-контракту.
- `proposal_rejected`: JSON получен, но предложение нарушает схему или разрешённые пути.
- `proposal_validated`: предложение прошло структурную проверку; код не запускался.

Запросы без ключей и ответы транспортов проверены автоматически с имитацией API. Факт прохождения таких тестов не подтверждает живой платный вызов на пользовательском аккаунте.

## Задачи, источники и файлы

План по правилам связывает каждую выбранную цель с `project-context` и обнаруженными источниками. Модель возвращает название, описание, задачи и полное содержимое новых предлагаемых файлов. Каждая задача содержит `evidence_ids`, `acceptance_criteria` и `file_paths`; вымышленные ID и файлы без задачи отклоняются. ID карточек имеют префикс `catalog:`; длинные идентификаторы не обрезаются до коллизий, а для сверхдлинных используется хеш. Это проверка ссылочной целостности, а не достоверности источника или релевантности цитирования.

Принимаются от 1 до 5 файлов, каждый до 12 000 байт UTF-8, суммарно до 48 000 байт. Разрешены только новые относительные ASCII-пути:

```text
docs/contributions/<name>.md
tests/proposals/<name>.py
workbench/experiments/<name>.py
```

Для всех трёх каталогов допустимы расширения `.md`, `.txt`, `.json`, `.py`. Файлы JSON дополнительно разбираются строгим парсером. Эти примеры не предписывают запуск Python-файлов: содержимое всех кандидатов остаётся данными.

Запрещены абсолютные пути, traversal, symlink в существующих компонентах пути, повторные имена, существующие файлы, скрытые и `__`-компоненты, `config`, `scripts`, `.github`, `.git`, `.env`, а также `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `CODEX.md` независимо от регистра. Ни инструкции для будущих агентов, ни изменения CI, ни файлы конфигурации моделью не принимаются. Одно нарушение отклоняет всё предложение, без частичной публикации безопасной на вид части.

Проверка пути и схемы не является анализатором безопасности произвольного Python. Кандидат может содержать ошибочный код или текст. До ручного review он не должен импортироваться, запускаться тестовым раннером, автоматически подключаться в production или получать секреты.

## Выходы и дедупликация

В указанном каталоге создаются три файла:

1. `cycle.json`: фактические запросы и статусы, карточки, источники, план, ограничения.
2. `proposal.json`: `status: none` с пустыми файлами либо `status: validated` с полным содержимым кандидатов, задачами и обязательными `review_required: true`, `code_executed: false`.
3. `report.md`: краткая сводка для человека.

`cycle_id` — SHA-256 канонического представления конфигурации, нормализованных карточек, выбранного поставщика и режима. Время получения карточки и время запуска в идентификатор не входят: одинаковые существенные входы дают одинаковый ID для дедупликации черновиков PR. Изменение карточек или конфигурации даёт новый ID. Это не кэш ответов и не механизм межзапускового ограничения расходов. Время запуска хранится отдельно в `created_at`.

Каталог вывода и конечные файлы не могут быть symlink. Содержимое каждого отчёта сначала записывается во временный файл с эксклюзивным созданием, затем заменяется целевой файл. Кандидаты из JSON не материализуются этим модулем. Публикация ветки — отдельный этап, для которого предусмотрена повторная проверка ограничений.

## Что проверено тестами

`tests/test_autonomy.py` проверяет реальный offline-проход по локальному каталогу и CLI, стабильность ID, сохранение URL источников и разных длинных идентификаторов, отказ до сети для неверной конфигурации, ограничения полномочий модели, отсутствие чтения постороннего файла, фиксацию одного запроса API, обе структуры API-запросов/ответов, отсутствие credentials в результатах, отказ при перенаправлении/ошибочном MIME/слишком большом/незавершённом ответе, строгий JSON, пути и symlink, запрещённые файлы инструкций, ограничения UTF-8 и атомарное отклонение всего предложения.

Отдельные API-ответы в этих тестах имитированы. Живая проверка каталогов и реальные статусы GitHub сохраняются в отчёте о поставке версии. Ни тесты, ни черновик PR не подтверждают самостоятельное участие внешних агентов, полезность произвольного предложения или биологическую эффективность платформы.
