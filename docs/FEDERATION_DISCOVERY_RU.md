# Обнаружение участников и инструментов федерации

Модуль `workbench.federation.discovery` выполняет ограниченный поиск метаданных и инспекцию явно заданной Agent Card. Он не подключает найденный endpoint, не запускает код или модели, не отправляет приглашения и не предоставляет права доступа. Независимая идентификация владельца и пригодность для научной задачи остаются отдельными этапами.

## Покрытие

| Источник | Реализованное действие | Ограничение |
|---|---|---|
| Agentverse | Поиск публичных карточек через существующий `society.directory` | Поисковый API использует POST; это запрос каталога, не сообщение агенту |
| Hugging Face models | Поиск публичных метаданных модели | Модель не является самостоятельным агентом; веса не загружаются |
| Hugging Face datasets | Поиск публичной карточки набора данных | Карточка не означает право доступа к самим данным |
| Official MCP Registry | GET `/v0.1/servers?search=…&limit=…&version=latest` | Поиск по имени сервера; MCP-сервер не обязательно автономный агент |
| Явный HTTPS seed | GET одной JSON Agent Card | Только публичный адрес и стандартный порт 443 |
| Явный Tor v3 onion seed | GET одной JSON Agent Card через заранее настроенный локальный SOCKS5 | Только заданный адрес; Tor не устанавливается и не запускается модулем |
| Закрытые базы и частные агентные сети | Автоматический поиск не реализован | Нужен официальный адаптер и доступ от оператора |

Система не обнаруживает «всех агентов интернета». Закрытые сети не предоставляют общего каталога; поддержка транспорта Tor сама по себе не создаёт индекса onion-сервисов. Обход списков onion, сканирование адресов и обход контроля доступа отсутствуют.

## API поиска

```python
from workbench.federation.discovery import discover

result = discover(
    query="research",
    providers=["agentverse", "huggingface_models", "huggingface_datasets", "mcp_registry"],
    limit=5,
    online=False,
    root=".",
    data_class="public",
)
```

- `providers=None` выбирает четыре встроенных источника. Разрешены от одного до четырёх разных провайдеров.
- `limit` — целое число от 1 до 8 **на провайдера**; максимум 32 карточки до дедупликации.
- `online=False` использует общий локальный curated registry. Он не имитирует ответы выбранных внешних каталогов: в provenance стоит `retrieval_kind=bundled_registry`, а счётчик запросов равен нулю.
- `online=True` допускается только для `data_class="public"`. Классификацию задаёт вызывающая сторона; это не автоматический DLP-анализ. Персональные геномы и медицинские сведения в поисковый запрос не передаются.
- Результат содержит `query`, `mode`, `data_class`, `items`, `provider_reports`, `requests`, `limitations`. Отчёт каждого провайдера содержит число запросов, число результатов и обезличенные ошибки. Ошибка одного каталога не превращается в выдуманные карточки.
- Для фиксированных каталогов допускаются системные proxy-переменные, необходимые в некоторых управляемых средах. Карточки, возвращённые ими, не вызываются автоматически.

## API инспекции Agent Card

```python
from workbench.federation.discovery import inspect_card

candidate = inspect_card("https://operator.example/.well-known/agent-card.json")
# Для реально известного, проверенного v3 onion-адреса:
# candidate = inspect_card(onion_card_url, tor_proxy="127.0.0.1:9050")
```

Вызов возвращает непосредственно нормализованного кандидата. Основные поля: `id`, `name`, `entity_type`, `url`, `protocol`, `protocol_version`, `capabilities`, `self_reported_capabilities`, `collaboration`, `provenance`, `seen_at`, `retrieved_at`, `network_layer`, `status`, `readiness`, `limitations`. `url` указывает на прочитанную карточку. Выполняющий endpoint из A2A-карточки не вызывается и не переносится в исполняемую конфигурацию.

`protocol="A2A"` означает формат карточки, распознанный ограниченным парсером. Модуль принимает `protocolVersion` либо версию из `supportedInterfaces`; это не тест совместимости RPC. `readiness="reviewed"` означает чтение метаданных, а `status="card_inspected_not_connected"` явно указывает, что подключения нет. Идентификация и возможности остаются `self_reported`.

Валидационные и транспортные ошибки возвращаются как `ValueError`; сообщения не содержат ответ сервера, настройки proxy или credentials. Неуспех Tor не вызывает запрос в clearnet.

## Явное намерение участвовать

Карточка может содержать локальное расширение Meta-Harness:

```json
{
  "meta_harness": {
    "collaboration": {
      "opt_in": true,
      "terms_url": "https://operator.example/collaboration-terms"
    }
  }
}
```

Только JSON boolean `true` в этом точном поле устанавливает `collaboration.opt_in=true`. Строка `"true"`, число `1`, маркетинговое описание, наличие в каталоге и инструкция в тексте не являются согласием. Это расширение проекта, а не обязательная часть A2A. Оно не аутентифицирует оператора, не выдаёт доступ и не заменяет отдельное принятие условий конкретного сотрудничества. Ссылка `terms_url` сохраняется как метаданные и не открывается автоматически.

## Ограничения транспорта

Для произвольного HTTPS seed действуют следующие ограничения:

1. Только `https`, порт 443, без userinfo, fragment, управляющих символов и перенаправлений.
2. DNS разрешается один раз. Каждая полученная запись проверяется: исключены private, loopback, link-local, multicast, reserved, IPv4-mapped и IPv6 transition/NAT64 диапазоны.
3. Сокет подключается к уже проверенному числовому IP. TLS проверяет сертификат исходного имени; повторного разрешения DNS при подключении нет.
4. Не используются переменные proxy окружения. Это может сделать прямую инспекцию недоступной в управляемой среде; модуль сообщит ошибку.
5. Допускается один GET, без cookies, токенов, credentials, redirect и сжатия. JSON карточки ограничен 128 KiB; глубина — 32, число узлов — 12 000. Дубли ключей, нечисловые NaN/Infinity и непечатаемые управляющие символы отклоняются.
6. Для операций установлен timeout 10 секунд и общий deadline 24 секунды; HTTP-сокет дополнительно прерывается по общему deadline. DNS использует ограниченное число daemon-потоков, чтобы вызывающий поток не ожидал системный resolver бесконечно.

Tor поддерживается только для корректного **v3 onion**: base32-декодирование, версия 3 и двухбайтовая checksum SHA3-256 проверяются до подключения. Допускаются `http:80` и `https:443`. Onion-имя передаётся proxy в SOCKS5 как `ATYP=DOMAIN`; локальный DNS для него не используется. Proxy должен быть loopback IP literal с явным портом, например `127.0.0.1:9050`, `socks5h://127.0.0.1:9050` или `socks5h://[::1]:9150`, без пароля и имени пользователя. Модуль не может установить, что за выбранным SOCKS5 endpoint действительно находится Tor: эту конфигурацию обеспечивает оператор. Подключение к указанному локальному proxy — единственное разрешённое обращение к loopback в данном транспорте.

## Проверка и источники

Тесты `tests/test_federation_discovery.py` проверяют публичность адресов, смешанные DNS-ответы и pinning, отсутствие вызовов найденных endpoint, строгий opt-in, повреждённые и чрезмерные JSON, отказ от redirect, отсутствие утечки текста транспортной ошибки, Tor v3 checksum, SOCKS5 domain handshake без DNS и отсутствие сети в offline-режиме. Tor-тесты используют поддельный транспорт; они не являются подтверждением живого соединения с onion-сервисом. Доступность внешних каталогов проверяется отдельным online smoke.

Официальные источники, просмотренные 24 сентября 2026 года:

- [Official MCP Registry API](https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/api/official-registry-api.md).
- [Registry OpenAPI](https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/api/openapi.yaml).
- [Official Registry Reference](https://registry.modelcontextprotocol.io/docs).

Записи MCP берутся из `servers[].server`; статус — из `_meta.io.modelcontextprotocol.registry/official`. Пакеты, `environmentVariables`, команды запуска, remotes и authentication-параметры не выполняются и не превращаются в установленный плагин.
