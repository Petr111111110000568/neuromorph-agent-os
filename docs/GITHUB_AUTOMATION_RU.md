# Автоматический цикл GitHub: обнаружение → предложение → ревью

Версия конфигурации: 0.9. Проверено по документации и API 24 сентября 2026 года. Состояние конкретных запусков и подключений публикуется отдельно: наличие workflow в исходниках само по себе не подтверждает его запуск на GitHub.

## Что работает без внешних ключей

После публикации на основной ветке workflow **Research autonomy** выполняет ограниченный поиск в публичных каталогах, систематизирует найденное и сохраняет отчёт с задачами. Триггеры: изменение конфигурации автоматизации на основной ветке, ежедневное расписание **06:23 UTC** и кнопка **Actions → Research autonomy → Run workflow**. GitHub может задерживать плановые запуски; это не служба с гарантированным временем исполнения. `AUTONOMY_ENABLED=false` в переменных репозитория останавливает новые циклы этого workflow.

По умолчанию вызовы платных моделей выключены. Программа честно сохраняет состояние без ответа LLM; она не подменяет его заранее написанным «ответом агента». Найденная карточка модели, MCP-сервера или агента — ресурс для оценки, а не подтверждение подключения или согласия участвовать. Поиск не выполняет регистрации, приглашения и запуск чужого кода.

**GitHub Models не используется**: официальная страница сообщает о прекращении сервиса 30 июля 2026 года. Старые инструкции с `models: read` не являются рабочей настройкой этого проекта.

## Как включается внешний вычислительный вклад

Настройки находятся в **Settings → Secrets and variables → Actions**. Сам ключ добавляйте как *Repository secret*, а переключатели — как *Repository variable*.

| Тип | Имя | Значение и назначение |
|---|---|---|
| Secret | `OPENAI_API_KEY` | Ключ разрешённого OpenAI API-проекта |
| Secret | `ANTHROPIC_API_KEY` | Ключ разрешённого Anthropic API-аккаунта; нужен только для этого провайдера |
| Variable | `AUTONOMY_ALLOW_MODEL_CALLS` | `true` разрешает один ограниченный запрос за цикл |
| Variable | `AUTONOMY_PROVIDER` | `auto`, `openai`, `anthropic` либо `none`; при включённых вызовах и пустой переменной используется `auto` |
| Variable | `AUTONOMY_ENABLED` | `false` приостанавливает весь workflow; иначе он включён |

При `auto` выбирается один доступный ключ: сначала OpenAI, затем Anthropic. Модели и лимиты ответа указаны в `config/autonomy.json`. Конфигурация не устанавливает SDK и не даёт модели инструменты выполнения команд. Лимит — один запрос без автоматического повторения; текущий предел ответа — 3000 токенов. Это ограничение количества запросов, а не точный денежный бюджет: расходы зависят от тарифа и входного контекста провайдера. Если требуется жёсткий бюджет, задайте его у провайдера до включения вызовов.

Обычная подписка ChatGPT не заменяет OpenAI API-ключ. Существующая интеграция ChatGPT с GitHub — отдельный путь работы с репозиторием; она не превращается автоматически в секрет для GitHub Actions. Подключение нативного кодирующего агента или задачи ChatGPT требует отдельного фактического подтверждения в отчёте о развёртывании.

Модели получают ограниченный публичный контекст проекта, цели и карточки источников. Их ответ рассматривается как недоверенное предложение. Программа не передаёт им токен публикации GitHub, не исполняет предложенный код и не выдаёт дополнительные разрешения по тексту ответа.

## Два независимых задания

1. **discover**: токен GitHub имеет `contents: read`. При выключенном разрешении вызовов провайдерские секреты вообще не добавляются в окружение шага. При включении они доступны только шагу единственного запроса. Результат сохраняется как данные в artifact `autonomy-cycle-<run_id>-<attempt>`.
2. **publish**: отдельное окружение, без ключей AI-провайдеров. Из проверенного commit основной ветки берётся `scripts/publish_autonomy.py`; он запускается с `python3 -I`. Только этому шагу передаётся временный `GITHUB_TOKEN` с правами `contents: write` и `pull-requests: write`. Данные скачиваются из artifact того же запуска и проверяются повторно.

Оба задания проверяют основную ветку; `pull_request_target` отсутствует. Checkout не сохраняет credentials. Генератор и publisher не выполняют команды из ответа модели. Токен GitHub не даёт publisher права обходить правила веток или организационные ограничения.

## Что может попасть в PR

Разрешены только новые текстовые файлы в трёх каталогах:

- `docs/contributions/` — обзоры, методические предложения и ограничения;
- `tests/proposals/` — предлагаемые тесты для последующей проверки;
- `workbench/experiments/` — отдельные предлагаемые эксперименты.

Пределы: до пяти файлов, до 12 000 UTF-8 байт каждый и до 48 000 байт в сумме; расширения `.md`, `.txt`, `.json`, `.py`. Пути с обходом каталогов, скрытые файлы, `__init__.py`, файлы инструкций `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `CODEX.md`, конфигурации и скрипты автоматизации запрещены. Publisher заново проверяет отсутствие файла в закреплённом дереве основной ветки и не допускает родительские symlink/submodule. Неполное дерево Git API также приводит к отказу от публикации.

Git API создаёт дерево и commit с обычными файлами `100644`, отдельную ветку `autonomy/proposal-<hash>` и **draft PR**. До PR проверяется, что ветка содержит только ожидаемые добавления с совпадающими хешами содержимого. Код из предложения не записывается поверх работающих модулей publisher и не исполняется в задании с правами записи. Изучение `.py` как данных не является испытанием этого кода.

Хеш набора файлов используется для идемпотентности. Повтор одного предложения не создаёт второй PR; уже закрытые предложения повторно не открываются. После частичного сбоя существующая ветка проверяется и может быть использована повторно. При несовпадении ветки никакого force push не происходит. Расписание и ручные запуски сериализуются; при трёх открытых PR от этого канала новые предложения сохраняются только в artifact.

Автослияния и автоматического включения модулей нет. Пользователь рассматривает источники и diff, испытывает предлагаемое изменение и решает о слиянии. Результат модели или успешный CI не подтверждает биологическую гипотезу.

## Артефакты и ошибки

Artifact цикла содержит `cycle.json`, `report.md`, `proposal.json`. Отдельный artifact `autonomy-publication-<run_id>-<attempt>` содержит `publish.json`. Срок хранения — 14 дней; для долговременного хранения выгрузите необходимые результаты либо примите подходящий PR. Это ограниченные результаты конкретного запуска, а не постоянная глобальная память агентов.

| Статус publisher | Значение |
|---|---|
| `pull_request_created` | GitHub подтвердил создание draft PR |
| `already_proposed` | Такое предложение уже оформлено, новых записей нет |
| `skipped` | Валидированного изменения нет или дерево уже совпадает |
| `artifact_only` | Сохранены данные; PR не подтверждён. Причина указана в `reason` |

`github_auth_or_policy` с HTTP 401/403 означает, что GitHub отказал в операции: например, токену недостаточно прав либо в репозитории запрещено создавать PR из Actions. В последнем случае проверьте **Settings → Actions → General → Workflow permissions → Allow GitHub Actions to create and approve pull requests**. Переключатель GitHub объединяет создание и одобрение; этот workflow сам PR не одобряет. Если политика организации запрещает действие, используйте artifact для обычного PR в пределах разрешений. Скрипт не меняет политику сам. После отказа PR API созданная ветка может остаться; автоматического удаления чужих веток нет.

`Core checks` использует только `contents: read`, не получает API-ключи и запускает полный `unittest` и `doctor`. По текущей документации GitHub, PR, созданный с `GITHUB_TOKEN`, может поставить CI в состояние ожидания подтверждения. Используйте штатную кнопку **Approve workflows to run**, если GitHub её показывает. Прототип не обходит эту проверку и не обещает безусловный автоматический CI после каждой публикации.

## Локальная воспроизводимость

```sh
python -m workbench.autonomy --config config/autonomy.json --output-dir runtime/autonomy --online --provider none
python -I scripts/publish_autonomy.py --proposal runtime/autonomy/proposal.json --output runtime/autonomy/publish.json
python -m unittest discover -s tests -p 'test_publish_autonomy.py' -v
```

Без `GITHUB_TOKEN` и `GITHUB_REPOSITORY` publisher сохраняет квитанцию `artifact_only`; он не пытается искать credentials на компьютере. Проверки publisher используют подменённый GitHub API: создание PR, дедупликация, гонки создания ветки/PR, запрещённая политика, лимит открытых PR, новые пути, symlink, запрет policy-файлов и отсутствие исполнения кода. Это не доказательство фактического вызова провайдера или публикации на удалённом GitHub; для этого нужен журнал соответствующего реального запуска.

## Закреплённые действия и источники

### Необязательная проверка настоящего Unreal Agent

Отдельный workflow **Optional Unreal protocol verification** запускается вручную либо при изменении его файлов, адаптеров или реестра в `main`. Он не добавляет стороннюю сборку в обычный `Core checks`. Задание имеет только `contents: read`, не получает ключи AI-провайдеров, собирает закреплённый Unreal Agent и проверяет протокол через локальный HTTP fixture. Срок выполнения ограничен 15 минутами.

Локальные команды для Linux AMD64:

```sh
python3 scripts/bootstrap_unreal.py
python3 scripts/bootstrap_unreal.py --install --pin-registry
python3 scripts/smoke_unreal.py
```

Первая команда показывает план без установки. Вторая явно собирает исходники `unreallabsai/unreal-agent` на commit `1b9f778453f411c029b39b85102aaefb95e7e48d`, проверяет зависимости и две группы upstream-тестов, затем закрепляет хеш полученного исполняемого файла только в локальном `config/harnesses.json`. Она не публикует изменения конфигурации на GitHub. Обычные запуски приложения не устанавливают этот harness автоматически.

Используется отдельный Go 1.27.1 вне дерева проекта. Прямой официальный tar-адрес при проверке вернул HTTP 404, поэтому основной проверенный способ — официальный [Go toolchain module ZIP](https://proxy.golang.org/golang.org/toolchain/@v/v0.0.1-go1.27.1.linux-amd64.zip). Его содержимое сверяется по закреплённому `h1:MeqkXdYlyiVdqJXENOTyX7xd8QjDM/mxR52RKOFBS0M=` из [официальной checksum database](https://sum.golang.org/lookup/golang.org/toolchain@v0.0.1-go1.27.1.linux-amd64). Проверка реализует [документированный алгоритм Hash1](https://github.com/golang/mod/blob/master/sumdb/dirhash/hash.go). `GOWORK=off` исключает влияние постороннего `go.work`; `go mod verify` проверяет кэш зависимостей. При несовпадении пина установка останавливается.

Исполняемый файл находится в `runtime/harnesses/unreal-agent-runner`, а доказательства сборки — в `runtime/harnesses/unreal-build.json`. Бинарник не включается в Git. Smoke проверяет настоящий процесс через тот же `HarnessRegistry.run`, который использует приложение: один локальный запрос Responses, отсутствие доступных инструментов, `store:false`, SSE и завершённое JSONL-событие ответа. Это проверка совместимости протокола с синтетическим ответом, не работа настоящей модели. Статус `live_authenticated` остаётся `false`.

В GitHub smoke пишет новый `runtime/harnesses/unreal-protocol.json`; загружается только этот artifact. Поэтому ошибочная удалённая сборка не выдаёт сохранённый в исходниках старый отчёт за результат текущего запуска. Отчёт локальной проверки находится в `data/unreal_validation.json`.
