# Cognitive OS, OpenClaw, Mimik и Мира: аудит для NeuroMorf

Дата проверки: 26 сентября 2026 года. Режим: публичные первоисточники, выборочное статическое чтение. Установка, импорт навыков в действующего агента, выполнение стороннего кода и модельные вызовы не выполнялись. Издержки API: 0.

## Решение для интеграции

Cognitive OS пригоден как источник формата журнала решений и калибровки гипотез. OpenClaw пригоден как отдельный подключаемый исполнитель с собственными зависимостями, правами и состоянием. Mimik пригоден как источник концепции записи воспроизводимого пользовательского протокола. Мира пока не предоставляет подтверждённого публичного кода или открытого доступа. Ни один из этих проектов не содержит сам по себе локальный научно валидированный «мозг».

Предлагаемый первый конечный результат: один проектный журнал prediction → observation → assessment и один протокол MCP-исполнителя с ограниченным набором инструментов, квитанцией и восстановлением после сбоя. Текущий stdlib core сохраняется. Массовое подключение всего каталога навыков не требуется для этого результата.

## Cognitive OS

Это именно указанный eugenexonr/cognitive-os, а не другая одноимённая IDE. В дереве 50 entries, включая каталоги; существует шесть Claude Code SKILL.md, шаблоны Cursor/Codex и протоколы boot/anti-drift/boris. В исследованном дереве не найден MCP-сервер или inference runtime.

Полезные идеи: отдельные kernel/решения/наблюдения, фиксация прогноза до результата, отметка неподтверждённого утверждения, пересмотр только затронутой части решения. Заявленная эффективность основана на опыте одного human–AI участника; перенос на научную валидность или надёжность разных моделей не доказан. «Обучение» здесь означает изменение записей/инструкций, а не обучение весов LLM. [README](https://github.com/eugenexonr/cognitive-os/blob/7e0811f2c79444ca80a456f29a0c0f86c7283234/README.md).

Конкретные ограничения исходников:

- `cos-careful` прямо называет себя мягким слоем поведения. Это не запрет ОС, ACL или песочница.
- `cog-update.sh` получает mutable origin/main и переписывает перечисленные framework-файлы. Его --check проверяет локальное состояние без fetch и не доказывает актуальность относительно upstream. Такой updater нельзя использовать для принятого pin без отдельной проверки diff.
- Обещание «zero dependencies» относится к Markdown-методике. `compact_decisions.py` импортирует yaml, поэтому этот вспомогательный скрипт требует отдельной зависимости.
- Компактор сначала перезаписывает decisions.md, затем archive.md. Между этими write нет общей транзакции: прерывание может оставить неполную миграцию. Для нашей многопроцессной системы нужен SQLite transaction/immutable event log, а не прямое копирование этой операции.

Первичные файлы: [cos-careful](https://github.com/eugenexonr/cognitive-os/blob/7e0811f2c79444ca80a456f29a0c0f86c7283234/drivers/claude-code/cos-careful/SKILL.md), [updater](https://github.com/eugenexonr/cognitive-os/blob/7e0811f2c79444ca80a456f29a0c0f86c7283234/cog-update.sh), [компактор](https://github.com/eugenexonr/cognitive-os/blob/7e0811f2c79444ca80a456f29a0c0f86c7283234/scripts/compact_decisions.py).

## OpenClaw

Официальность подтверждена ссылкой с [openclaw.ai](https://openclaw.ai/) на репозиторий openclaw/openclaw. Рассмотренный package.json имеет version 2026.9.6, Node `>=24.16.0 <25 || >=26.1.0`, pnpm 12.4.2, MCP SDK 1.30.0, native/PTY/браузерные зависимости. Наличие локальной модели и контейнерной среды нужно проверять отдельно; бесплатность кода не означает бесплатность внешнего inference. [Закреплённый package.json](https://github.com/openclaw/openclaw/blob/718bf2ccae9f42735ce95eda37f0abbd67ceb821/package.json).

Ключевая граница: один gateway рассчитан на одного оператора или взаимно доверяющую команду. Документация не обещает изоляцию враждебных пользователей внутри общего gateway. Несандбоксированные агенты по умолчанию имеют широкую видимость сессий; корпоративные арендаторы должны получать отдельные изолированные gateway cells, а не только разные имена агентов. Root/admin-доступ к хосту и конфигурации равен полномочиям оператора. [Trust model](https://github.com/openclaw/openclaw/blob/718bf2ccae9f42735ce95eda37f0abbd67ceb821/docs/gateway/security/trust-model.md).

MCP native client поддерживает stdio, Streamable HTTP и SSE, toolFilter и policy. Сохранённое определение сервера не доказывает доступность; нужен probe. Stdio запускает программу с доступом процесса, поэтому «подключить MCP» — это выдача конкретных возможностей, а не просто добавление справочника. Вывод сервера/сайта считается недоверенными данными; он не может сам расширять allowlist. [MCP](https://github.com/openclaw/openclaw/blob/718bf2ccae9f42735ce95eda37f0abbd67ceb821/docs/tools/mcp.md).

В снимке обнаружен 51 top-level bundled SKILL.md. Выборочно прочитаны пять: healthcheck, taskflow, mcporter, github, clawhub. Это не аудит всех сторонних навыков ClawHub. Полезный образец — TaskFlow: owner/revision/checkpoint и проверка фактической mutation receipt; durable state сам по себе не является scheduler. Скрипты и зависимости этих навыков целиком не проверены, навыки не установлены. [TaskFlow skill](https://github.com/openclaw/openclaw/blob/718bf2ccae9f42735ce95eda37f0abbd67ceb821/skills/taskflow/SKILL.md).

Рекомендуемый стартовый профиль интеграции: loopback gateway с серверной аутентификацией; явные MCP tool allowlists; выделенный project workspace; host-shell и elevated выключены; отдельные секреты каждого adapter; ресурсы/таймаут/лог/stop; право подключения LAN-узла отдельно от права запуска команд. Контрольные значения сверять с версией, не вставлять в боевую конфигурацию автоматически. [Hardened baseline](https://github.com/openclaw/openclaw/blob/718bf2ccae9f42735ce95eda37f0abbd67ceb821/docs/gateway/security/hardened-baseline.md).

Официальная документация предписывает считать third-party skills недоверенным кодом, поддерживает policy перед установкой и предупреждает об области секретов. Проверка подписи/хеша/статического сканера не доказывает отсутствие вредоносного поведения. Нельзя честно заявить «удалены все вредоносные части всех навыков» после выборочного чтения. Новый pin, дополнительные зависимости, dynamic downloads и runtime-поведение требуют новой проверки. [Skills security](https://docs.openclaw.ai/tools/skills#security).

## Mimik

[TenChat6161273](https://tenchat.ru/media/6161273-mimik-prevraschayet-vashi-deystviya-v-brauzere-v-instruktsiyu) прямо называет westpoint-io/mimik; это подтверждённая связь, а не догадка по имени. В pin package.json version1.2.0, WXT/React/TypeScript, pnpm10.32.1; build включает postinstall wxt prepare.

Исходник wxt.config.ts запрашивает Chrome host_permissions `<all_urls>`, tabs/scripting/webNavigation/unlimitedStorage; Firefox использует optional_host_permissions. Нужен осознанный выбор разрешённых сайтов и тест без личных данных. Режим Smart Blur основан в том числе на regex; он не гарантирует обнаружение произвольных секретов. Browser profile со всеми аккаунтами не следует включать в evidence pack.

По коду AI description получает DOMContext и настроенный ключ/endpoint, после чего вызывает провайдера. Поэтому утверждение «данные никогда не покидают устройство» не применимо к включённым внешним AI/voice/TTS. Без этих функций запись/экспорт можно рассматривать как локальный кандидат, но фактический сетевой trace здесь не выполнялся.

Первая интеграция в NeuroMorf: импорт заранее просмотренного экспортированного руководства как артефакта с источником, hash и project_id. Записанные шаги — данные, не автоматические shell/browser команды. Расширение сейчас не устанавливалось; блокировка страницы управления расширениями в текущем окружении не обходилась.

Источники: [manifest](https://github.com/westpoint-io/mimik/blob/27b6928a6942612357ed514da2ebbe3bdddc181d/wxt.config.ts), [AI description](https://github.com/westpoint-io/mimik/blob/27b6928a6942612357ed514da2ebbe3bdddc181d/src/entrypoints/background/ai-description.ts), [blur regex](https://github.com/westpoint-io/mimik/blob/27b6928a6942612357ed514da2ebbe3bdddc181d/src/core/blur/regexes.ts).

Проверка выборочная, не полноценный аудит безопасности. Исследовательские материалы не загружались в рабочий prompt как доверенные системные навыки. Основной код NeuroMorf не изменён.

## Контракт интеграции NeuroMorf: состояние не равно возможности

Все три открытых проекта имеют статус `reviewed_not_installed`. Новые подключения не активированы. Реестр `config/external_harness_pins.json` — описание проверенного снимка, а не исполняемый установщик или разрешение. Мира — `unavailable_public_code`.

| Компонент | Документированный транспорт/механизм | Установлен в этой работе | Активное соединение проверено | Что допускается следующим шагом |
|---|---|---|---|---|
| Cognitive OS | Markdown, Python helpers; MCP не найден | Нет | Нет | Собственная реализация CognitiveDecisionLog в текущем транзакционном хранилище |
| OpenClaw | MCP stdio, Streamable HTTP, SSE; отдельный gateway | Нет | Нет | Чистая закреплённая сборка, fake-server probe и adapter receipt |
| Mimik | Browser extension, экспорт руководства; MCP не найден | Нет | Нет | Ручной импорт просмотренного guide как артефакта |
| Мира | Публичный API в просмотренных материалах не найден | Нет | Нет | Следить за официальным релизом и условиями, без фиктивного адаптера |

CognitiveDecisionLog — название предлагаемого нашего модуля, не API upstream. Он хранит исходный прогноз, уровень уверенности, проверяемое наблюдение, источник и revision. Результат не перезаписывает исходный прогноз. Изменение плана не изменяет отдельно принятую политику допуска, права MCP или operator digest.

Capability separation означает отдельные полномочия чтения источников, записи project artifacts, исполнения проверенного расчёта, доступа к MCP и подключения LAN-узлов. Модель выбирает действия внутри выданного профиля; текст навыка/чата не выдаёт новые права. Даже предоставленный пользователем широкий доступ к файловой системе не доказывает надёжность скачанного кода или изоляцию чужих данных.

Из предлагаемой поставки исключены автоматический mutable-main updater Cognitive OS, массовая установка навыков, браузерный захват по умолчанию и внешние AI/voice-вызовы из Mimik. Будущее включение отдельного компонента должно быть явным, версионированным и отражаться отдельной фактической квитанцией.

Для offline-дистрибутива понадобятся отдельно проверенные runtime, dependency lock/wheelhouse или npm store, платформенные native binaries, лицензии/third-party notices, манифест размеров/хешей и модельные веса с их собственной лицензией. Одного Git commit недостаточно для воспроизводимого offline installer. Не добавлять в архив cookies, профили браузера, личные переписки, секреты и состояние другого арендатора. Runtime, исполнение MCP и модельные веса в этой работе не упакованы и не испытаны.
