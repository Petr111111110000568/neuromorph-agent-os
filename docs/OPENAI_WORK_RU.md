# OpenAI, ChatGPT Work и рабочее окружение Meta-Harness

Проверено: **18 сентября 2026 года**. Назначение: воспроизводимая настройка исследовательского проекта. Сведения о продуктах сверены с официальной документацией OpenAI; состояние аккаунта и среды приведено отдельно. Этот документ не изменяет настройки аккаунта.

## Что представляет собой текущий помощник

В этом чате работает агент Codex в ChatGPT Work: он может исследовать источники, работать с файлами и кодом, вызывать доступные инструменты, делегировать независимые задания советникам и проверять результаты. Это наблюдаемые возможности сеанса. Точное имя модели, текущий тариф, доступные остатки кредитов и права администратора нельзя надёжно вывести из текста ответов или старой истории пользователя.

Официальная документация описывает Work как среду выполнения задач с проверяемыми результатами, файлами, плагинами и разрешёнными инструментами; локальный и облачный режимы отличаются местом исполнения. Для облачного режима не требуется постоянно включённый пользовательский компьютер, но доступность возможностей определяется конкретной средой и аккаунтом. [Get started with ChatGPT Work](https://learn.chatgpt.com/docs/get-started-with-work).

Документация моделей рекомендует выбирать настройки по сложности задачи и проверять доступные варианты в переключателе аккаунта. В проекте следует записывать фактически использованные `provider`, `model`, версию промпта, параметры и бюджет каждого запуска. Настройка максимального уровня рассуждений сама по себе не заменяет тесты и независимую проверку. [Models](https://learn.chatgpt.com/docs/models).

## Четыре разных контура

| Контур | Для чего подходит | Что требуется отдельно |
|---|---|---|
| ChatGPT Work в браузере | Исследование, код, документы, советники, подключённые сервисы, проверяемые артефакты | Доступные аккаунту инструменты и разрешения; сохранение результатов между сеансами |
| Codex CLI / приложение / IDE | Работа с репозиторием и локальными инструментами | Установленный клиент, вход, рабочая машина, применяемые клиентом настройки |
| OpenAI API и Agents SDK | Собственное веб-приложение с управляемыми вызовами моделей | API-аутентификация, бюджет, сервер приложения, хранение состояния и наблюдаемость |
| Вычислительные исполнители проекта | Анализ данных, ML, симуляции, долгие задания | Отдельные CPU/GPU-ресурсы, зависимости, изоляция и хранилище |

Вход в ChatGPT и авторизация API — разные механизмы. В локальных клиентах Codex доступны вход через ChatGPT и API-ключ; использование API-ключа оплачивается через OpenAI Platform по API-тарифам. Подключение ChatGPT в браузере не подтверждает доступ API у разрабатываемого приложения. [Authentication](https://learn.chatgpt.com/docs/auth).

Responses API позволяет приложению самостоятельно управлять циклом вызовов. Agents SDK предоставляет цикл агента, передачу работы между агентами, сессии, трассировку и возобновляемые проверки разрешений. **Рекомендация для Meta-Harness:** хранить исследовательский процесс и результаты в собственной базе, а SDK использовать как заменяемый исполнитель задач. [Agents SDK](https://developers.openai.com/api/docs/guides/agents-sdk).

## Skills, плагины, MCP и советники

Skill задаёт повторяемую процедуру и ресурсы. Плагин объединяет устанавливаемые возможности: skills, MCP-инструменты и поддерживаемые компоненты. Для проекта полезны отдельные процедуры поиска источников, критики утверждений, проверки воспроизводимости и подготовки релиза. [Skills & Plugins](https://learn.chatgpt.com/docs/skills-and-plugins).

**Ключевое ограничение:** браузерный ChatGPT не читает локальный `.codex/config.toml`. Запись такого файла внутри временного контейнера не подключает MCP ко всему аккаунту. В hosted Work инструменты MCP приходят через установленные плагины. Конфигурация `config.toml` относится к поддерживаемым локальным клиентам; MCP может использовать STDIO либо Streamable HTTP. [Model Context Protocol](https://learn.chatgpt.com/docs/extend/mcp).

MCP стандартизует доступ к инструментам и контексту. Из этого не следует автоматическая переносимость любого научного пакета, изоляция процессов или корректность результатов. Для включения пакета нужны адаптер, декларация входов и выходов, проверка версии, лицензии и зависимостей. Это архитектурный вывод для нашего проекта.

Советники могут параллельно исследовать независимые вопросы. Они используют доступные родительскому чату инструменты и наследуют ограничения; параллельность увеличивает расходы. Разделение файлов между исполнителями уменьшает конфликты. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Рекомендуемый состав совета:

| Роль | Проверяемый результат |
|---|---|
| Систематизатор | Источники, метаданные, понятия, дубликаты, карта утверждений |
| Эксперт по доказательствам | Первичный источник, независимая проверка, ограничения и противоречия |
| Генетика и эпигенетика | Границы применимости опубликованных методов и наборов данных |
| ML и статистика | Базовые модели, разделение данных, неопределённость, тест на утечку |
| Квантовые вычисления | Постановка задачи, классический baseline, стоимость кодирования и измерений |
| Архитектор | Контракты плагинов, хранение, восстановление после сбоя |
| Инженер реализации | Рабочий код и подтверждающие тесты |
| Независимый рецензент | Воспроизводимость и несоответствия заявленным возможностям |

Эти роли — распределение работы, а не восемь независимых научных подтверждений. Согласие моделей не считается экспериментальным доказательством.

## Снимок окружения

Локальное основание: `data/environment_status.json`, созданный проверкой основного агента. Подключение GitHub проверено им отдельным успешным запросом профиля.

| Возможность | Статус при проверке | Практическое следствие |
|---|---|---|
| Python 3.12.14, NumPy, SciPy | Доступны | Можно запускать небольшой вычислительный прототип |
| Node, npm, Git | Доступны | Возможна сборка интерфейса и ведение исходников |
| ffmpeg, ffprobe | Доступны | Возможны технический анализ и подготовка видео |
| PyTorch, FastAPI, Uvicorn, pytest | Не установлены в проверенном Python | Не считать готовым ML/GPU-сервером; зависимости добавлять под конкретный исполнитель |
| Codex CLI | Не установлен | Команды `codex` здесь пока неприменимы |
| Docker / Podman | Не обнаружены | Изоляция контейнерами не подтверждена |
| Bubblewrap | Программа есть; создание namespace отклонено средой | Запрещено заявлять рабочую изоляцию только по наличию бинарного файла |
| GitHub | Подключение аккаунта подтверждено | Доступ к конкретному репозиторию проверяется отдельно |
| Context7 | Выполнены успешные resolve и query по документации MCP | Проверена конкретная интеграция; свежесть каждого результата сверяется с первоисточником |
| `OPENAI_API_KEY`, `META_LLM_*` | В проверенном окружении не заданы | Живые вызовы моделей из нового приложения не настроены |
| Предыдущая scratch-сборка | Не найдена | Старые сообщения о пройденных тестах не подтверждают новую сборку |

Это снимок, а не постоянные свойства аккаунта. Новый сеанс должен заново проверять окружение. Не выводить секреты при диагностике.

## Почему подходит веб-приложение

**Рекомендуется веб-консоль исследовательского проекта:** реестр источников, очередь задач, советники, каталог плагинов, просмотр результатов, журнал изменений и отчёты. Интерфейс должен показывать фактические статусы: «рассчитано», «не проверено», «требуется подключение», «гипотеза», «ошибка».

Sites умеет размещать веб-приложения, поддерживает D1 для структурированных данных и R2 для файлов. Сохранение версии и публикация — разные этапы; URL deployment обозначает работающую опубликованную версию. Доступ и возможности зависят от аккаунта. [Sites](https://learn.chatgpt.com/docs/sites).

Для данной предметной области существенны ограничения Sites: документация не допускает обработку Protected Health Information; не заявляет residency данных или inference при запуске; не поддерживает некоторые фоновые службы, private networks и raw TCP. Поэтому предложенная архитектура использует Sites для консоли и открытых/синтетических демонстрационных данных. Персональные геномные данные и тяжёлые вычисления требуют отдельной подходящей инфраструктуры. Это проектное решение, а не утверждение, что такая инфраструктура уже подключена. [Sites: limits and unsupported uses](https://learn.chatgpt.com/docs/sites).

Рабочая граница компонентов:

1. Веб-консоль создаёт задачу и показывает состояния и артефакты.
2. Сервер проверяет права, сохраняет задачу и выдаёт идентификатор.
3. Планировщик назначает доступный исполнитель с явным бюджетом.
4. Исполнитель сохраняет входы, версии, результаты и ошибки.
5. Рецензент проверяет критерии; неуспех возвращается в очередь исправлений.

Это рекомендуемая производственная схема. Её наличие в документе не означает, что серверы, GPU или защищённое хранилище уже развёрнуты.

## Длительная автономная работа

Для долгой задачи официальная документация рекомендует задавать результат, ограничения и критерии готовности. Hosted Work продолжает работу в рамках чата; Goal mode не расширяет доступ и разрешения. [Long-running work](https://learn.chatgpt.com/docs/long-running-work).

Scheduled tasks могут запускать проверки по расписанию. В веб-режиме они используют сохранённый промпт, контекст и подключённые инструменты, **но не сохраняют локальную папку или worktree между запусками**. Исходники и состояние должны находиться в долговременном доступном источнике. Наличие инструментов планирования не доказывает, что конкретное расписание уже создано. [Scheduled tasks](https://learn.chatgpt.com/docs/automations).

API `background` запускает отдельный ответ асинхронно и позволяет опрашивать его статус. Это полезно для длинного модельного вызова. Из документации не следует, что один такой вызов заменит недельный планировщик научных работ. Очередь, checkpoint, повторные попытки, дедупликация, остановка по бюджету и восстановление остаются задачами приложения. [Background mode](https://developers.openai.com/api/docs/guides/background).

## Проектные инструкции для повторного запуска

Ниже предложен текст для инструкций проекта. В локальном репозитории соответствующие нормы можно закреплять в `AGENTS.md`. Документация описывает загрузку этих файлов локальным Codex по уровням проекта; наличие файла не доказывает изменение настроек hosted Work. [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

> Работай на русском языке. Цель Meta-Harness — воспроизводимые исследования и инженерная проверка методов. Разделяй первичные данные, опубликованные результаты, модельные прогнозы и гипотезы. Для существенного утверждения сохраняй источник, дату проверки и границы применимости. Назначай параллельным исполнителям независимые задачи и непересекающиеся файлы. Для каждого вычисления сохраняй входы, версии, seed, метрики и ограничения. Не называй тестовый или синтетический результат подтверждённым прогнозом для взрослого организма. Перед завершением проверяй заявленные пользовательские сценарии, сохраняй исходники и артефакты, обновляй статус незавершённых работ. Секреты передавай только через предусмотренное защищённое хранилище. Учитывай реальные полномочия и бюджет; не заявляй подключение либо публикацию без подтверждения инструмента.

Практический критерий завершения программной версии: новый пользователь может восстановить проект из сохранённого исходника, открыть интерфейс, добавить источник, запустить доступный вычислительный модуль, увидеть результат и ограничения, перезапустить приложение без потери состояния и получить отчёт. Для версии с LLM дополнительно требуется реальная проверка авторизации и одного полного цикла с моделью; имитация ответа этого не заменяет.

Исследовательская платформа может ускорять поиск, сравнение методов и вычислительную проверку. Программная работоспособность не подтверждает возможность безопасно ускорить эволюцию взрослого организма или проектировать новые органы: это отдельные научные задачи с экспериментальными критериями.
