# Slack: опциональная отправка квитанций облачного совета

Состояние: **подготовлено в PR; не развёрнуто в main и не проверено живой отправкой**.

## Назначение

Workflow `.github/workflows/council-health.yml` выполняет только наблюдение
публичного Git-журнала. Дополнительный шаг, если настроен секрет,
передаёт в Slack короткую квитанцию: статус
`scheduled_or_waiting` / `degraded` и коды причин из жёсткого белого списка.
Не передаются исходные отчёты, запросы агентов, имена пользователей,
данные рабочих станций или содержимое исследований.

Частота не изменена: текущее расписание cloud workflow
`52 2,8,14,20 * * *` (4 раза в сутки UTC), также доступен ручной запуск.
Это не непрерывное выполнение ИИ и не прямая интеграция Dots, Slack-чата
или ChatGPT. Данный мост не может отправлять команды агентам и не проверяет
состояние локального ПК, провайдеров LLM и самого Slack-бота.

## Активация после код-ревью и слияния PR

1. Создать Slack Incoming Webhook для **разрешённого пользователем канала**.
2. В GitHub `Settings → Secrets and variables → Actions` создать
   repository secret с именем `SLACK_WEBHOOK_URL` и значением webhook.
   **Не размещать адрес в issue, исходниках, логах, диалоге или файлах.**
3. Запустить `Council cloud health` вручную на `main` и проверить в
   назначенном Slack-канале квитанцию. При отсутствии секрета шаг
   безопасно пропускается. Ошибка отправки не блокирует health receipt:
   в workflow задан `continue-on-error: true`.

Webhook ограничен HTTPS и адресами
`hooks.slack.com/services/...` / `hooks.slack-gov.com/services/...`.
При ошибке не выводятся секреты, адреса webhook, сырые отчёты и тела ответов.
Доставку не следует считать подтверждённой, пока нет реального сообщения
и связанного запуска Actions.

## Приёмка

- `python -m unittest discover -s tests -v`
- `python -m workbench doctor` (если CLI предусматривает этот маршрут,
  иначе используйте указанную в README команду doctor)
- без секрета: ноль исходящих HTTP-запросов
- с тестовым транспортом: только один HTTP POST JSON без приватных полей
- workflow продолжает загружать артефакт даже при сбое уведомления
- основной реестр в `main` не изменяется до ревью и merge

**Ограничение:** наличие рабочего Slack/Dots-коннектора внутри отдельного
интерфейса ChatGPT не эквивалентно правам этого GitHub workflow. Для
публикации нужен отдельный GitHub secret.
