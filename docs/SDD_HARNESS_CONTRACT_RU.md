# SDD для текущего облачного изменения

[Статья AiManual](https://ai-manual.ru/article/harness-dlya-ii-razrabotki-kak-dva-agenta-zamenili-komandu-i-pochemu-sdd-stal-novyim-standartom/) изучена и сопоставлена с первичными материалами. Применяем конкретный контракт изменения и отдельную проверку результата.

[Исследование arXiv2605.23950](https://arxiv.org/html/2605.23950) действительно содержит отношение7.80: это отношение дисперсий между harness и моделями в данном эксперименте (100 задач, три модели, три harness, два прогона). Это не ускорение разработки в7.8раза. Рассказ о56днях, замене3–4разработчиков и80% приёмки не снабжён установленным нами воспроизводимым первичным кейсом. SDD здесь инженерный подход, а не доказанный универсальный стандарт.

[Spec Kit для существующих проектов](https://github.com/github/spec-kit/blob/main/docs/guides/existing-projects.md) поддерживает ограниченные изменения существующего кода; переписывать всю систему или устанавливать ещё один framework не требуется. [Anthropic](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) описывает ограниченную функцию, проверки поведения, Git checkpoint и журнал прогресса. Раздельный контекст reviewer уменьшает влияние самооценки автора, но не доказывает независимость ошибок.

## Передача рецензенту

Пакет содержит task_id, parent, base_commit, условия, точный код/публичные ссылки, контрпример коллеги и ожидаемый результат. Рецензенту не передаётся внутренняя цепочка рассуждений автора. Установка, протокольная проверка, полученный ответ, review и scientific validation имеют разные значения. Согласие двух модельных ролей не заменяет облачные проверки.

Для следующего M02 сначала сопоставить контракт с существующими Queue/Brain/Society: не создавать второй lease engine. Нужны два синтетических проекта, дедупликация, ограниченные попытки, проверка владельца и версии при commit и два последовательных облачных запуска с сохранённым состоянием. Конкретный отрицательный сценарий — старый worker возвращается после expiry и пытается перезаписать новый принятый результат. Эта миссия ещё не выполнена данным PR.

Статья не служит основанием сохранять refresh tokens в browser localStorage: шифрование там не устраняет доступ вредоносного JavaScript ([OWASP](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html)). Секреты и приватные чаты в публичный evidence pack не входят.
