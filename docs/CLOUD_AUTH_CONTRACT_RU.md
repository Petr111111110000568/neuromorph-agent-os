# Личный вход в облачный НИОКР-интерфейс

Статус: реализация и offline fixture-тесты подготовлены. Этот документ не подтверждает выпуск облачного сервиса, регистрацию OAuth-приложения или успешный живой вход. Расходы на модельные вызовы — 0; этот модуль моделей не вызывает.

## Граница доступа

`workbench.cloud_auth.CloudAuth` допускает только заранее заданный числовой Yandex ID владельца. Первого посетителя нельзя назначить владельцем автоматически. Email, отображаемое имя, имя Яндекс-логина и данные браузера не используются как подтверждение владения. Ответ профиля должен содержать тот же `client_id`, что зарегистрирован в серверной конфигурации.

Сервер получает через менеджер секретов четыре переменные:

- `NEUROMORPH_PUBLIC_ORIGIN`: точный HTTPS origin без завершающего `/`, пути, query или fragment.
- `NEUROMORPH_YANDEX_CLIENT_ID`: ID зарегистрированного OAuth-приложения.
- `NEUROMORPH_YANDEX_CLIENT_SECRET`: секрет только на сервере.
- `NEUROMORPH_YANDEX_OWNER_ID`: заранее проверенный числовой ID владельца.

Отсутствующая или неверная настройка должна остановить облачный запуск; нельзя переходить к локальному режиму без авторизации. Callback приложения регистрируется как `<public_origin>/auth/yandex/callback`. Облачный запуск требует доверенного HTTPS reverse proxy, закрытого прямого HTTP-порта, постоянного хранилища проекта и одного серверного процесса. Это не функции `http.server` или данного OAuth-модуля. X-Forwarded-* не являются доказательством доверия сами по себе.

## Протокол

`begin()` создаёт случайные state, отдельную привязку браузера и PKCE verifier. Только хеши state и привязки хранятся в памяти. Браузер получает `__Host-neuromorph_oauth`, провайдер — S256 challenge; запрашивается только `login:info`. Срок потока — 10 минут, максимум 32 незавершённых потока.

`callback(query: dict[str,str], cookie_header: str)` проверяет state и привязку браузера. HTTP-адаптер обязан сохранить пустые query-параметры и отвергнуть дубликаты **до** преобразования в словарь. Состояние атомарно потребляется до запроса токена, поэтому конкурирующие callback не вызывают повторного обмена. Даже ошибка провайдера требует нового начала входа. Авторизационный код и токен не сохраняются на диске.

OAuth transport обращается только к фиксированным `oauth.yandex.ru/token` и `login.yandex.ru/info?format=json`. Запрещены redirect и автоматическое чтение proxy-переменных. Каждый запрос имеет timeout 10 секунд и предел ответа 64 КиБ. Неправильный status, Content-Type, JSON, дубликаты JSON-ключей и non-finite значения отклоняются. Внешние исключения заменяются фиксированным кодом ошибки без секретных данных. Автоматических повторов нет.

После проверки owner/client выдаётся случайная часовая серверная сессия; в памяти хранится хеш её cookie. Cookie `__Host-neuromorph_session` имеет `Secure; HttpOnly; SameSite=Lax; Path=/`, без Domain. Одновременно допускается до 16 сессий. Перезапуск сервера завершает все сессии и потоки входа. Для горизонтального масштабирования потребуется отдельное общее хранилище с атомарным потреблением state; текущая реализация его не заявляет.

`session(cookie_header)` возвращает копию `{subject, csrf_token, expires_at}`. Все приватные GET/HEAD и экспорты требуют сессию. `authorize_write(cookie_header, origin, csrf_token)` дополнительно требует точного Origin и случайного CSRF-токена именно этой сессии. `logout` требует ту же защиту и удаляет только текущую сессию. Пустой Origin не допускается при записи. CSRF-токен можно получить только через защищённый `/api/session`, без CORS и с `Cache-Control: no-store`.

Статическая оболочка может открываться до входа, поэтому в HTML/JS запрещены встроенные приватные переписки, сведения аккаунтов и секреты. URL callback, Cookie, CSRF, Authorization, тело token-response нельзя писать в access/error-журналы ни приложения, ни reverse proxy. Нужны отдельные ограничения частоты и числа подключений на reverse proxy: лимит pending-потоков ограничивает память, но сам по себе не предотвращает DoS.

## Проверка

`tests/test_cloud_auth.py` использует только локальные fixtures: owner/client mismatch, session expiry/restart, origin/CSRF, подмена cookie, replay и конкурентный callback, ограничение ёмкости, санитаризация ошибок, PKCE, фиксированные endpoints и ограниченный OAuth transport. Реальные OAuth-запросы и credentials не используются. Наличие тестов не означает, что они запущены: итоговое число и результат необходимо брать из облачного CI проверенного commit. Дополнительно необходимы интеграционные проверки HTTP-сервера на 401/403 для всех приватных маршрутов и отсутствие обхода через HEAD/неподдерживаемые методы.
