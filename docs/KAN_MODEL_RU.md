# KAN в Meta-Harness 0.8

Плагин `kan_benchmark` выполняет обучение композиционной сети Колмогорова — Арнольда и сравнение с MLP и линейной регрессией. Он не требует PyTorch, GPU или внешнего API. Исходный код: `workbench/kan.py`; воспроизводимый набор экспериментов: `python scripts/verify_kan.py`.

## Что изучено и что встроено

## Вычислительная модель

Архитектура — `2 → H → 1`, где `H` от 2 до 4. Все `3H` рёбер содержат функцию

\[
\phi_e(u)=a_e u+\sum_{k=1}^{K}c_{e,k} B_k(u),\qquad
h_j=b_j+\sum_{i=1}^{2}\phi^{(1)}_{ji}(x_i),\qquad
\hat y=b_o+\sum_{j=1}^{H}\phi^{(2)}_j(h_j).
\]

Обучаются все `a`, `c` и смещения узлов. Для `spline` используются кусочно-линейные базисные функции с постоянным продолжением базисной части за границами сетки. Для `rbf`: `exp(-z²)`. Для `wavelet`: `(1-z²)exp(-z²/2)`. Здесь `z=(u-center)/width`; сетка равномерная и фиксированная. Диапазоны сетки: `[-1.25,1.25]` на входных рёбрах и `[-2,2]` на выходных; линейная часть продолжает действовать за этими границами. Это не клеточная морфогенетическая модель и не модель коры.

Производные функции рёбер по входу позволяют распространять ошибку через второй слой в первый. Таким образом обучается именно композиция функций, а не только последний линейный слой над неподвижными признаками. Для каждой функции выгружаются коэффициенты, границы сетки и 33 точки кривой. Вместе со смещениями узлов они задают обученную KAN первого seed.

Число параметров KAN: `3H(K+1)+H+1`. Ширина tanh-MLP выбирается близкой к этому числу: у неё `4W+1` параметров. Разница не превышает двух параметров. Классическая линейная регрессия имеет три параметра и обучается решением нормальных уравнений с выбором главного элемента.

## Протокол эксперимента

- Область входов — равномерная выборка из `[-1,1]²`.
- Аддитивная функция: `sin(πx₀)+0.5cos(πx₁)`.
- Функция взаимодействия: `sin(πx₀x₁)+0.2cos(πx₀)`.
- Для каждого seed создаются независимые train и test потоки RNG. Шум добавляется только в обучающие ответы; test содержит 80 новых точек и чистые значения функции.
- KAN и MLP получают одни и те же train-примеры и последовательности minibatch из 12 индексов. Инициализации независимы, соответствуют архитектурам и полностью сбрасываются между seed.
- Optimizer — Adam, `beta1=0.9`, `beta2=0.999`, `eps=1e-8`, ограничение каждой компоненты градиента диапазоном `[-10,10]`. По умолчанию 140 обновлений, одна скорость 0.02 для KAN и MLP.
- Нет ранней остановки, отбора checkpoint, подбора гиперпараметров или выбора победителя по test. Кривые показывают только train MSE. Итоговый test рассчитывается после фиксированного числа обновлений.

Такое сравнение контролирует данные и число обновлений, но не равенство FLOPs, времени или оптимальности настройки. Три seed — небольшой методический эксперимент; SD по seed не является доверительным интервалом клинического эффекта. Результаты не переносятся автоматически на геномику, реальные временные ряды, язык или работу мозга.

Это не доказывает превосходства KAN над хорошо настроенным MLP: настройки обеих архитектур фиксированы, MLP получает всего 140 обновлений, а задачи специально малы и низкоразмерны. Дальнейший честный benchmark требует отдельного validation split, равного бюджета поиска гиперпараметров, большего числа seed и задач, а затем единственного закрытого test.

## Проверки и границы запуска

`tests/test_kan.py` проверяет конечными разностями каждый параметр обоих слоёв для всех трёх базисов, производные по входу и градиент MLP. Дополнительно проверяются изменение обоих слоёв при обучении, воспроизводимость, конечность JSON, ограничения параметров и точность выгруженных кривых. Изменение только test-ответов не меняет выученные функции и train-кривые.

Максимальный разрешённый контракт: `H=4`, `K=8`, 180 шагов, 128 обучающих примеров, три seed. После регистрации плагина каждый из трёх вариантов успешно запущен через настоящий `plugin_worker.py` с ограничениями CPU 5/6 секунд и адресного пространства 512 МиБ. Измерено 0.484–0.602 секунды CPU, stdout 36 998–37 064 байта; код завершения каждого процесса — 0. Параметры, хеши вывода и результаты сохранены в `examples/kan_runtime_limits.json`. Ограничение `RLIMIT_FSIZE` в worker относится к размеру обычного файла, а размер stdout здесь отдельно измерен и оказался менее 1 МиБ. Это измерение конкретной Linux-среды, не гарантия скорости любого ПК.

## Применение в исследовательской платформе

KAN может быть исполнителем конкретных задач низкоразмерного surrogate modeling: аппроксимация численной модели, сравнение функциональных зависимостей, исследование ошибок и визуализация обученных функций. Роль KAN не равна агенту: для автономного исследования нужен оркестратор, протокол задачи, источники, проверка качества и критерий остановки. Функции рёбер сами по себе не являются найденными причинными законами.

Оригинальные pykan/FastKAN/Wav-KAN целесообразно подключать отдельными окружениями после закрепления commit, зависимостей и лицензии, затем сравнивать на том же контракте данных. Их текущий статус в этом выпуске — `reviewed_not_installed`; автоматический запуск исходных обучающих сценариев не настроен. Например, исходный `wavKAN.py` загружает MNIST и запускает цикл обучения уже на уровне модуля, поэтому простой импорт всего сценария не является подходящим адаптером.
