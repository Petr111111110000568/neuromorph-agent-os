# Копирование исходников и границы интеграции

`SnapshotStore` реализует конкретный этап: получить закреплённый публичный ZIP исходников, проверить структуру и поддерживаемые лицензионные тексты, сохранить неизменённые файлы, LICENSE/NOTICE, хеши и запись происхождения. Итоговый статус — **`source_inspected_not_executed`**. Исходники не импортируются, не устанавливаются и не запускаются.

Это позволяет начать воспроизводимую интеграцию открытого инструмента. Снимок не копирует облачную службу, её модель, учётную запись или права на данные. Авторизация в EGA и других контролируемых репозиториях остаётся отдельным процессом.

## Вызов

Через HTTP API платформы:

```json
{
  "repository": "EGA-archive/ega-download-client",
  "commit": "5ec6c4cd37cc67142285051bdbd725c824da1384",
  "license_spdx": "Apache-2.0"
}
```

Тело передаётся в `POST /api/society/snapshot`. Тот же объект принимает `SnapshotStore(root, state_dir).inspect(body)`. `items()` возвращает сохранённые записи. `close()` закрывает SQLite.

Адрес загрузки формируется только как `https://codeload.github.com/<owner>/<repo>/zip/<40-hex-commit>`. Пользователь не задаёт произвольный URL. `main`, `latest`, теги и сокращённые хеши не допускаются. Перенаправления запрещены; HTTPS проверяет сертификат стандартными средствами Python. Используется настроенный в среде прокси выхода в интернет, если он существует; его параметры не копируются в отчёт.

Для локальной проверки возможен дополнительный `archive_path` к ZIP. Тогда происхождение явно записывается как **`user_supplied_archive_unverified_origin`**, а `source_url` остаётся пустым. Указанный пользователем commit не становится доказанным происхождением локального архива. Архив должен содержать один корневой каталог с LICENSE.

## Проверки копии

| Проверка | Действующее ограничение |
|---|---|
| Сжатый архив | До 10 МиБ |
| Суммарный размер распакованных файлов | До 40 МиБ |
| Количество элементов | До 1000, включая каталоги |
| Коэффициент сжатия | Не более 200 для файла размером более 1 МиБ |
| Лицензионный текст и NOTICE | До 256 КиБ, UTF-8 |
| Время сети | 10 с на сетевую операцию, проверяемый бюджет загрузки 25 с |
| Форматы сжатия | ZIP stored/deflate, без шифрования |
| Пути | Запрещены выход из каталога, абсолютные пути, обратные косые черты, управляющие символы, конфликт имён, Windows device names |
| Типы файлов | Запрещены символьные ссылки и специальные файлы |
| Исполнение | Нет; извлечённые файлы получают режим без executable bits |

Архив предварительно проверяется, затем содержимое читается с проверкой CRC. Каждая принятая копия получает отдельный непредсказуемый каталог `state/snapshots/snapshot_…/`. В нём сохраняются оригинальный `source.zip`, каталог `files/` и `inspection.json`. Реестр находится в `society_snapshots.sqlite3`.

Запись включает SHA-256 архива, каждого файла и лицензии; точный запрошенный commit; время получения; количество файлов; объём; признаки проверки. Наличие commit в URL и корректный HTTPS-ответ не равны независимой проверке Git-объектов или подписей автора. Имя GitHub-организации также не удостоверяет юридическую принадлежность проекта.

## Лицензии

Первый поддерживаемый путь принимает MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause и ISC в консервативно поддерживаемых стандартных формах. Сопоставляется полный нормализованный текст условий: для Apache и MIT — закреплённые хеши стандартного текста, для BSD/ISC — полные шаблоны с ограниченными полями владельца прав. Префикс допускает только стандартные заголовки и copyright; одного SPDX-заголовка недостаточно. Root LICENSE должен соответствовать заявленному семейству. Дополнительные LICENSE/COPYING и каталоги `LICENSES` также проверяются. NOTICE сохраняются. Commons Clause, неизвестные/комбинированные тексты, изменённые условия, нестандартные префиксы и неподдерживаемые лицензии отклоняются.

Это консервативный текстовый фильтр, **не юридическая экспертиза**. Он может отклонить допустимую нестандартно оформленную лицензию; он не способен доказать отсутствие условий за пределами исследованных файлов, например в отдельном соглашении. Условия зависимостей, которые устанавливаются отдельно, не проверены. Перед публикацией или промышленным развёртыванием нужно проверить все применимые тексты, авторские уведомления, требования к изменениям и права на модель/данные отдельно.

## После снимка

1. Изучить README и лицензию конкретного commit; выбрать одну нужную функцию.
2. Составить контракт входа/выхода и классификацию передаваемых данных.
3. В отдельном окружении закрепить зависимости и проверить их лицензии.
4. Реализовать адаптер с ограничениями времени, памяти, сети и доступных действий.
5. Проверить адаптер на открытом контрольном наборе, записать версии и хеши.
6. Подключать закрытые данные только через законные credentials и согласованные scopes; результаты проверять отдельно от корректности программы.

Действующий SnapshotStore выполняет получение и инспекцию исходников. Эти последующие шаги не объявляются выполненными автоматически.

## EGA: практический кандидат

Исходники [ega-download-client](https://github.com/EGA-archive/ega-download-client) — клиент загрузки данных. Это полезный компонент доступа к исследовательскому репозиторию, а не автономный исследовательский интеллект. Лицензия исходников не предоставляет доступ к человеческим геномным данным. Проверенный запрос закреплён на commit `5ec6c4cd37cc67142285051bdbd725c824da1384`; фактический результат исполнения сохранён в `examples/source_snapshot_run.json`. Получен ZIP **73 093 байта**, сохранено **63 файла / 180 920 байт**, root LICENSE соответствует поддерживаемому полному тексту Apache-2.0. SHA-256 архива: `7617768066955c0a854e182649596d5ba3a3c3b6a6c219f5a387ba1e6937e234`. Статус результата следует читать буквально: успешная инспекция не означает установленный или испытанный EGA-клиент.

Проверки модуля: `python -m unittest discover -s tests -p test_snapshots.py -v`. Они проверяют реальные границы архива, лицензионные отказы, фиксированный адрес, сохранение файлов без исполнения, очистку после ошибки и восстановление записей из SQLite.
