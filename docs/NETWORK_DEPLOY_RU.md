# Распределённый транспорт и исполнители v0.5

Сеть состоит из координатора с локальной SQLite, доверенных рабочих процессов и локальной веб-консоли. Координатор выдаёт задания по возможностям исполнителя, закрепляет аренду задания и сохраняет результат. Рабочие процессы можно запускать на разных компьютерах. Каждый получает задания по HTTPS; SQLite остаётся на диске координатора и не размещается на сетевой файловой системе.

## Что исполняется

Поддержаны два типа заданий:

| Тип | Реальное действие | Граница результата |
| --- | --- | --- |
| `simulation` | Запуск одного из закреплённых встроенных модулей через `Service.run`, отдельный Python-процесс, проверка хешей и лимиты | Синтетический вычислительный контроль; не прогноз изменений человека |
| `discovery` | Поиск метаданных через предусмотренные адаптеры либо поиск по локальному каталогу при `offline: true` | Найденная ссылка не означает проверенную статью или установленную платформу |

Задание не может передать команду оболочки, новый исполняемый плагин или произвольный URL для загрузки кода. Поле `root` также не принимается из задания. Обнаруженный научный пакет сначала попадает в каталог возможностей. Для его фактического использования нужен отдельный проверенный адаптер и окружение.

## Быстрый запуск на одном компьютере

Из корня распакованного проекта:

```bash
python3 -m workbench local-network --workers 2
```

Откройте `http://127.0.0.1:8765`. Команда поднимает UI, hub, координатор кампаний и два самостоятельных worker-процесса. В этой конфигурации служебный токен создаётся в памяти и передаётся дочерним процессам через среду. Для воспроизводимой проверки без внешнего поиска:

```bash
python3 scripts/demo_network.py
```

Демонстрация запускает отдельный hub-процесс и два worker-процесса, исполняет два закреплённых вычислительных задания и два поиска по локальному каталогу. Она проверяет статусы, разные PID/владельцев, происхождение реальных вычислительных результатов и отсутствие bearer-токена в файлах состояния. Временные базы удаляются после проверки. Это проверка процессов и сетевого протокола на одном компьютере, а не испытание межмашинного развёртывания.

## Развёртывание на нескольких компьютерах

1. Установите Python 3.11+ и одну проверенную версию проекта на координаторе и исполнителях. Обязательных pip-зависимостей у сетевого ядра нет.
2. Выдайте доверенным исполнителям случайный общий секрет длиной не менее 32 печатных ASCII-символов через переменную `META_HUB_TOKEN`. Используйте секрет-хранилище операционной среды. Не помещайте значение в аргументы команд, JSON, Git или настройки браузера.
3. Подготовьте действительный TLS-сертификат и закрытый ключ для имени координатора. Для приватного CA передайте исполнителям сертификат центра, а не закрытый ключ сервера.
4. Запустите три компонента координатора с одним каталогом состояния:

```bash
python3 -m workbench --data-dir ./state serve
python3 -m workbench --data-dir ./state hub --host 0.0.0.0 --port 8766 --certfile /secure/hub-fullchain.pem --keyfile /secure/hub-key.pem
python3 -m workbench --data-dir ./state daemon
```

Команды выполняются в отдельных процессах/терминалах либо под управлением внешнего менеджера процессов. Веб-консоль остаётся на localhost. Hub предоставляет только рабочий протокол; он не является публичным интерфейсом постановки заданий.

5. На каждом исполнителе задайте ту же `META_HUB_TOKEN`, затем запустите процесс с уникальным идентификатором:

```bash
python3 -m workbench.network.worker --hub https://hub.example.org:8766 --id compute-01 --capabilities simulation --data-dir ./worker-state
python3 -m workbench.network.worker --hub https://hub.example.org:8766 --id discovery-01 --capabilities discovery --data-dir ./discovery-state
```

Для собственного CA добавьте `--ca-file /secure/research-ca.pem`. Проверка имени и цепочки сертификата остаётся включённой. Флага отключения TLS-проверки нет. HTTP разрешён только для loopback-адреса/localhost. Перенаправления запрещены, включая перенаправления на другой HTTPS-домен. Переменные HTTP_PROXY/HTTPS_PROXY намеренно не используются транспортом hub, чтобы bearer-секрет не уходил через автоматически настроенный прокси.

Ограничьте входящий порт hub адресами исполнителей. TLS и общий секрет обеспечивают защищённый канал для доверенной группы, но не превращают сервис в готовую многопользовательскую платформу.

## Протокол и восстановление

Все методы требуют `Authorization: Bearer …`, включая health. Максимальное тело транспортного сообщения — 1152 KiB; очередь дополнительно ограничивает полезную нагрузку задания 64 KiB и результат 1 MiB. Разрешены только конечные JSON-числа; повторяющиеся ключи и неожиданные поля отвергаются. Hub ограничивает число параллельных соединений и таймаут чтения. Запросы с заголовком `Origin` отклоняются; wildcard CORS не выдаётся.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/v1/health` | Доступность протокола |
| POST | `/v1/register` | Объявить ID исполнителя и возможности |
| POST | `/v1/claim` | Получить подходящее задание и lease-токен |
| POST | `/v1/heartbeat` | Продлить действующую аренду |
| POST | `/v1/finish` | Отправить результат или ошибку владельцем аренды |

Удалённых методов submit/cancel/delete нет. Постановка и отмена заданий выполняются через локальную управляющую поверхность координатора.

Аренда выдаётся на 60 секунд; исполнитель продлевает её каждые 15 секунд, пока выполняет задание. Каждый HTTP-запрос ограничен 8 секундами, временная сетевая ошибка повторяется не более трёх попыток с ограниченной задержкой. Ошибки авторизации и некорректных запросов автоматически не повторяются. При потере аренды результат не считается принятой работой; очередь отклоняет просроченного владельца. Повторная доставка того же завершения допустима. Просроченные задания возвращаются в очередь при её последующем обращении, пока не исчерпан лимит попыток.

Гарантия исполнения — **не менее одного раза**, а не ровно один раз. После сетевого сбоя вычисление может повториться. Внешние необратимые действия в имеющихся обработчиках отсутствуют; для будущих адаптеров потребуются собственные идемпотентные операции.

`--once` обрабатывает не более одного задания и завершает процесс также при пустой очереди. `--max-jobs N` ограничивает число полученных заданий, но не время ожидания пустой очереди. Без этих параметров исполнитель опрашивает координатор до остановки; самоперезапуск обеспечивает выбранный администратором менеджер процессов. `--poll-seconds` задаёт интервал опроса от 0.01 до 60 секунд.

## Границы доверия

- Общий bearer-секрет объединяет исполнителей в одну доверенную группу. Это не индивидуальные учётные записи, роли организаций или изоляция арендаторов. Участник группы может регистрировать ID; lease-токен дополнительно закрепляет принятие конкретного результата.
- Приложение не проверяет добросовестность удалённого исполнителя. Даже результат со статусом completed является сообщённым вычислительным результатом и требует научной проверки.
- Встроенные модули выполняются отдельными процессами с ограничениями, а не в контейнерной или VM-песочнице. Не устанавливайте непроверенный код в окружение доверенного worker.
- Приложение хранит данные и результаты на локальных дисках без собственного шифрования базы. Права ОС, защищённые резервные копии, ротация секретов и постоянный мониторинг относятся к развёртыванию.
- Задания discovery могут обращаться к предусмотренным публичным API; токен hub этим API не передаётся. Поиск метаданных не выполняет регистрацию на научных платформах и не принимает условия обслуживания от имени пользователя.
- Здесь не развёрнут облачный кластер, не предоставлены вычислительные квоты и не подключены персональные геномы. Проверка двух процессов на loopback и отдельная проверка TLS не равны проверке эксплуатации на нескольких физических узлах.
