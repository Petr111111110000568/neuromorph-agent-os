# Конечное расписание бесплатного discovery

`python -m workbench.autonomy.daemon` выполняет публичный поиск по уже разрешённым каталогам, сохраняет карточки в ограниченную SQLite-историю и обновляет план по правилам. Оно работает отдельным обычным Python-процессом и не зависит от лимита чата OpenAI. Это не самостоятельный LLM-исследователь: новые научные выводы и исполняемый код оно не генерирует.

Всегда используются `provider="none"` и пустая среда credentials, даже если конфигурация или среда запуска разрешают модели. Политика нулевых расходов проверяется перед запуском и перед каждым циклом. Процесс не создаёт аккаунты, не подключает обнаруженных агентов, не устанавливает пакеты, не скачивает исполняемый код и не меняет собственное расписание. Публичные каталоги имеют собственные ограничения доступности и частоты запросов; их ошибки отражаются в результатах цикла.

Все родительские каталоги и каталог outputs должны существовать. Например, из корня репозитория:

```text
python -m workbench.autonomy.daemon --config config/autonomy.json --output-dir runtime/autonomy --history-db runtime/discovery.sqlite --state-file runtime/discovery-schedule.json --stop-file runtime/discovery.stop --interval 3600 --max-cycles 168
```

Параметры `--config`, `--output-dir`, `--history-db` и `--state-file` обязательны. Интервал ограничен 900–86400 секундами; число циклов — 1–1000. Значения по умолчанию: 3600 секунд и 168 циклов — примерно семь дней при работающем компьютере. Первый цикл выполняется сразу, последующие — после интервала от завершения предыдущего. Время выполнения запросов добавляется к этому сроку. Процесс не регистрирует системный сервис или задачу ОС, не переживает выключение компьютера автоматически и не запускает собственную замену.

`--once` выполняет максимум один уже наступивший цикл. Если время ещё не наступило, возвращает `not_due` без ожидания. `--offline` сохраняет сетевой поиск выключенным и подходит для проверок. Изменение режима, конфигурации, путей, интервала или числа циклов требует нового явно выбранного state-файла: старое задание не сбрасывается молча.

State JSON хранит только идентификатор задания, UTC-время следующего запуска, счётчик завершённых циклов и короткий статус. После обычного перезапуска процесс продолжает по checkpoint; пропущенные интервалы не создают очередь догоняющих запросов. Внутри процесса интервалы отсчитываются монотонными часами. Межпроцессная блокировка не допускает два экземпляра с одним state-файлом. ОС освобождает блокировку после завершения процесса; небольшой `.lock` файл намеренно остаётся.

Создание указанного `--stop-file` останавливает расписание до следующего цикла или не позднее пяти секунд ожидания. Уже начавшийся ограниченный запрос каталога сначала завершается; немедленного прерывания сетевого вызова нет. После удаления stop-файла можно явно запустить ту же команду снова. Ctrl+C также завершает процесс.

Порядок сохранения: три файла цикла → SQLite-история → атомарный JSON checkpoint. Локальная ошибка прекращает выполнение без бесконечного повтора; счётчик завершений не увеличивается. Если процесс прервётся после результата, но до checkpoint, после перезапуска возможен повтор одного чтения каталогов: семантика **at-least-once**, а не exactly-once. Невалидные пути, ссылки/reparse points, неизвестные checkpoints и изменённая конфигурация отклоняются. Ограничения и требования ручного восстановления SQLite после аварии описаны модулем history; stale-результаты каталога не означают удаление источника.
