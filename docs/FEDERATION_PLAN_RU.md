# Федерация исследовательских агентов: инженерный план и права на воспроизведение

Исторический план от 18 сентября. Состояние реализации версии 0.7 от 24 сентября описано в [FEDERATION_DELIVERY_RU.md](FEDERATION_DELIVERY_RU.md); сравнение текущих первичных материалов — в [FEDERATION_RESEARCH_RU.md](FEDERATION_RESEARCH_RU.md). Планируемые функции ниже не следует считать автоматически подключёнными.

Дата проверки: 18 сентября 2026 года. Этот документ описывает проверенные внешние средства и план их подключения. Наличие записи в каталоге не означает подключения сервиса, договора с организацией или доказанного биологического результата. Исполнители Meta-Harness v0.5 используют правила и закреплённые вычислительные модули; из документации внешних LLM-агентов нельзя заключать, что они уже установлены внутри проекта.

## 1. Как распределить обязанности

Для сети нужны три независимых слоя: долговременное управление заданиями, межагентный обмен и доступ к инструментам. Один протокол не заменяет все три.

| Слой | Предлагаемое средство | Практическая роль | Чего оно не даёт автоматически |
|---|---|---|---|
| Состояние исследования | Существующая очередь Meta-Harness; затем LangGraph или Microsoft Agent Framework в отдельном worker | План, контрольные точки, возобновление, бюджет, отмена | Научная корректность, изоляция или право доступа |
| Делегирование самостоятельному агенту | A2A с закреплённой версией | Agent Card, задание, состояние, артефакт, запрос дополнительной информации | Доступ к внутренним моделям, весам или аккаунтам агента |
| Вызов инструмента | MCP с закреплённой версией | Обнаружение инструментов и типизированные вызовы | Планирование всего исследования или автоматическая выдача полномочий |
| Научные данные | API и официальные клиенты провайдеров | Метаданные, разрешённые наборы, вычислительные входы | Разрешение на перераспространение каждого набора |
| Доказательства | Собственный реестр утверждений и артефактов | Связь вопроса, источника, метода и результата | Превращение согласия агентов в независимый эксперимент |

[A2A](https://a2a-protocol.org/latest/) разделяет агентов и инструменты; официальный [MCP](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) определяет авторизацию транспорта. Авторизация HTTP использует OAuth; stdio получает credentials из окружения. У каждого исполнителя должны быть только необходимые права.

A2A создан Google и передан проекту Linux Foundation; это не сеть всех агентов Google. [Сообщение Linux Foundation](https://www.linuxfoundation.org/press/linux-foundation-launches-the-agent2agent-protocol-project-to-enable-secure-intelligent-communication-between-ai-agents). MCP действует в структуре LF Projects с собственными maintainers; участие организации в стандарте не доказывает, что конкретный найденный сервер принадлежит ей. [Управление MCP](https://modelcontextprotocol.io/community/governance).

## 2. Совместимость на дату проверки

Сайт спецификации A2A указывает выпущенную версию **1.0.0**. В GitHub найден tag `v1.0.1`, но его текст также обозначает протокол как 1.0.0; tag репозитория и объявленная версия протокола не должны смешиваться. Для прототипа следует закрепить конкретный SDK/commit и поддерживаемую версию. [Спецификация A2A](https://a2a-protocol.org/v1.0.0/specification/).

MCP указывает текущую версию **2026-07-28**: версия передаётся с запросом, `server/discover` сообщает возможности, а совместимость с прежним handshake описана отдельно. Ограниченный сервер Meta-Harness 2025-11-25 не становится совместимым с новым стандартом от переименования поля. Адаптер должен тестировать обе стороны либо честно объявлять старую версию. [Версии MCP](https://modelcontextprotocol.io/specification/versioning).

Agent Card — заявление поставщика о возможностях. При подключении проверяются домен, происхождение документации, выбранный транспорт и фактически разрешённые действия; отсутствующий endpoint нельзя достраивать догадкой. Внешние агенты не получают общую память, секреты и произвольное исполнение на координаторе.

## 3. Какие архитектуры воспроизводимы

**LangGraph / LangChain.** LangGraph подходит для графа исследования с контрольными точками и человеческим разбором спорных результатов. Его код под MIT; платформа LangSmith и сервисы моделей имеют отдельные условия. Рекомендуется отдельный worker, сохраняющий входы/выходы в формате Meta-Harness. Вся сеть не должна зависеть от присутствия этого worker. [Возможности](https://docs.langchain.com/oss/python/langgraph/overview), [сохранение состояния](https://docs.langchain.com/oss/python/langgraph/durable-execution), [лицензия](https://github.com/langchain-ai/langgraph/blob/main/LICENSE).

**Microsoft Agent Framework.** Python/.NET, модельные провайдеры, workflow, checkpointing и MCP удобны для смешанного парка исполнителей. Документация различает агента для открытой задачи и workflow для фиксированной последовательности. AutoGen переведён в maintenance mode; для новых узлов предпочтительнее Agent Framework, старые AutoGen-проекты можно оборачивать и мигрировать постепенно. [Обзор](https://learn.microsoft.com/en-us/agent-framework/overview/), [статус AutoGen](https://github.com/microsoft/autogen), [миграция](https://learn.microsoft.com/en-us/agent-framework/migration-guide/from-autogen/), [MIT](https://github.com/microsoft/agent-framework/blob/main/LICENSE).

**OpenAI Agents SDK и Responses.** SDK реализует приложение и делегирование, тогда как удалённая модель и hosted tools остаются внешними сервисами. MIT-лицензия SDK не передаёт веса моделей или право копировать аккаунт. Подключение требует действующего API-доступа, квот и контроля передаваемых данных. Официальная документация также описывает Secure MCP Tunnel для частных MCP-серверов; поддержка на данном аккаунте не проверена. [SDK](https://developers.openai.com/api/docs/guides/agents-sdk), [MCP](https://developers.openai.com/api/docs/guides/tools-remote-mcp), [лицензия SDK](https://github.com/openai/openai-agents-python/blob/main/LICENSE). Отсутствие обучения на API-данных по умолчанию не равнозначно отсутствию хранения: режимы хранения необходимо проверять по конкретной функции. [Управление данными](https://developers.openai.com/api/docs/guides/your-data).

**Anthropic Research.** Полезен опубликованный шаблон: ведущий исследователь, параллельные специалисты, долговременные артефакты, отдельная проверка ссылок. Это описание производственной системы, а не лицензия на её закрытую реализацию. Авторы отмечают высокие расходы токенов и сложности взаимозависимых задач. Поэтому стартовая сеть использует ограниченное число специалистов и измеряет стоимость полезного проверенного результата. [Инженерный разбор](https://www.anthropic.com/engineering/multi-agent-research-system). В более поздней авторской работе показаны проблемы координации равноправных длительно работающих агентов: сам рост числа участников не гарантирует прогресса. Это аргумент в пользу бюджета и явного владения задачами, а не доказательство биологической эффективности. [Исследование координации](https://www.anthropic.com/research/multiagent-systems).

## 4. Законный закрытый сегмент: dbGaP и EGA

Полезная закрытая часть интернета — это прежде всего авторизованные научные хранилища и частная инфраструктура. Доступность документации не означает доступности данных.

**dbGaP / NCBI / NIH.** Доступ к контролируемым данным требует соответствующего исследователя, институциональных полномочий, заявки и одобрения проекта. NIH описывает eRA/NIH credentials и требования к ответственному исследователю. Агент может подготовить список подходящих наборов, обоснование и форму заявки на основании достоверных данных пользователя. Он не может самостоятельно создать отсутствующую аффилиацию или выдать себе разрешение. [Официальная процедура NIH](https://sharing.nih.gov/accessing-data/accessing-genomic-data/how-to-request-and-access-datasets-from-dbgap).

**EGA.** Решение принимает Data Access Committee конкретного набора; доступ ограничен согласием участников и соглашением об использовании. Каждый заявитель имеет собственную учётную запись: регистрация не заменяет разрешение DAC. [Запрос данных](https://ega-archive.org/access/request-data/how-to-request-data/). Официальный pyEGA3 можно развернуть как отдельный клиент после выдачи доступа; он поддерживает возобновление, контроль целостности и выбор диапазонов при наличии индексов. Это downloader, не агент открытия новых знаний. [Документация pyEGA3](https://ega-archive.org/access/download/files/pyega3/).

Для Meta-Harness целевая схема: сервисный адаптер выполняется в разрешённом контуре, секреты доступны только ему; внешний планировщик получает допустимые метаданные и агрегаты. Персональные геномные файлы не пересылаются внешним LLM автоматически. Проверяются ограничения исходного набора на производные данные, хранение и экспорт; необходимость такой проверки не устраняется использованием Tor, VPN или собственного сервера.

## 5. Что означает цифровая копия

1. Для открытого ПО — получить точный commit, сохранить LICENSE/NOTICE и происхождение, проверить архив, затем отдельно собрать и проверить приложение в изолированной среде.
2. Для открытых весов — отдельно проверить лицензию весов, код, обучающие данные, ограничения применения и потребность в оборудовании. Лицензия wrapper не распространяется автоматически на модель.
3. Для закрытого сервиса — использовать опубликованный API/партнёрскую интеграцию; воспроизводить собственную архитектуру по открытым описаниям. Не извлекать закрытые веса, чужие credentials или сеансы.
4. Для научной статьи — сохранить библиографию, разрешённые выдержки и связь с результатом; наличие статьи в браузере само по себе не разрешает зеркалирование её полного текста.

MIT требует сохранять copyright и разрешительное уведомление. Apache-2.0 дополнительно требует учитывать уведомления NOTICE и обозначать изменения; точные обязанности сверяются с лицензией конкретной версии. [MIT LangGraph](https://github.com/langchain-ai/langgraph/blob/main/LICENSE), [Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0.txt). У MCP сейчас переход лицензирования: новые code/spec contributions Apache-2.0, иные документы CC-BY-4.0, часть старых вкладов остаётся MIT. У `python-sdk` отдельно проверена MIT. Поэтому одна надпись «MCP = MIT» недостаточна. [Лицензия проекта](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/LICENSE), [SDK](https://github.com/modelcontextprotocol/python-sdk/blob/main/LICENSE). У AutoGen тоже раздельные условия: код MIT, контент CC-BY-4.0; требуется учитывать оба файла.

Небольшой практический кандидат для проверки копирования: `EGA-archive/ega-download-client`, Apache-2.0, commit `5ec6c4cd37cc67142285051bdbd725c824da1384`. GitHub сообщил размер репозитория 447 KB; это метаданные репозитория, не измеренный размер ZIP. [Исходники](https://github.com/EGA-archive/ega-download-client), [лицензия](https://github.com/EGA-archive/ega-download-client/blob/master/LICENSE), [commit](https://github.com/EGA-archive/ega-download-client/commit/5ec6c4cd37cc67142285051bdbd725c824da1384). Его проверенная копия даст пример воспроизводимого снапшота. Она не докажет подключение EGA, доступ к геномам или выполнение исследования.

## 6. План реализации с критериями готовности

Сроки ниже — порядок работ и ориентиры для команды, не обещание фонового выполнения. Переход осуществляется по проверяемому результату.

| Этап | Работа | Условие завершения | Результат для пользователя |
|---|---|---|---|
| P0, текущий выпуск | Реестр организаций, типов сущностей, источников, лицензий; маршрутизация по классу данных; миссия и реестр утверждений | UI показывает documented/connected/tested/validated раздельно; неизвестный источник не становится доказательством | Видно, кто и чем может помочь, что уже работает |
| P1, 1–2 недели | Открытый поиск, отбор аннотаций, дедупликация DOI, контрсвидетельства, воспроизводимый методический контроль | Несекретная задача проходит поиск→артефакт→ограничения; повтор сохраняет происхождение и параметры | Проверяемая карта литературы и исполняемый вычислительный пример |
| P2, 2–3 недели | Один LangGraph или Agent Framework worker, подключённый LLM-провайдер, лимиты стоимости | Остановка по бюджету; возобновление после сбоя; внешний текст не исполняется как инструкция; trace без секретов | Диалог уточняет план и распределяет задачи между реальными модельными агентами |
| P3, 2–4 недели | Версионные MCP/A2A шлюзы, агентские карточки, идентичность, квоты, cancellation | Два независимо размещённых узла обмениваются заданием; недействительная авторизация/версия отвергается; повтор не удваивает платёж | Добавление собственных и партнёрских агентов через проверенные подключения |
| P4, после появления допуска | Изолированные адаптеры EGA/dbGaP/частных лабораторных хранилищ | Подтверждён scope данных; отозванный доступ прекращает операции; личные данные не утекают в поиск/trace | Работа с разрешёнными закрытыми источниками из той же панели |
| P5, отдельные научные проекты | Верификация одного вычислительного метода на открытом benchmark, затем внешняя репликация | Версия данных и кода, baseline, заранее определённая метрика, независимая проверка и отчёт ошибок | Научно ограниченный результат с измеренным качеством |

Критерий продуктивности — количество новых подтверждённых в своей области утверждений или воспроизводимых результатов на бюджет, а не число агентов, регистраций или прочитанных страниц. Для LLM-планировщика требуется сравнение с фиксированным workflow; если он дороже и не улучшает результат, он не включается по умолчанию.

Каждый будущий исполняемый plugin имеет manifest: источник/commit, лицензия, интерфейс, входные и выходные типы, допустимый класс данных, egress-домены, вычислительные лимиты, тестовый набор, срок перепроверки. Цепочка состояний: найден → документирован → исходники проверены → установлен → контракт проверен → benchmark пройден → допущен в конкретной области. Один тест не перескакивает всю цепочку.

## 7. Как пользователь получает результат

Основной интерфейс — веб-панель миссии. Пользователь вводит вопрос, область и ограничения; отмечает публичные/внутренние/чувствительные данные; задаёт бюджет и ожидаемый артефакт. Пример допустимой начальной задачи: «сопоставить опубликованные модели клеточного состояния и проверить воспроизводимость одного метода на открытых данных». Пожелание сформировать новые признаки организма сначала превращается в список проверяемых исследовательских вопросов и пробелов, без автоматического плана вмешательства.

Панель должна показывать: выбранные ресурсы и причины выбора; организацию по первоисточникам; фактический статус доступа; текущие задания и расходы; найденные свидетельства и противоречия; параметры и результаты расчёта; недостаточные данные; кнопки отмены, уточнения и экспорта. Учёные/операторы вводят оценку утверждения с обоснованием отдельно от автоматически найденных ключевых слов.

Раздел подключений предлагает проверенный OAuth/API-процесс конкретного провайдера. Секрет не вводится в обычный чат и не становится частью миссии. Если нужны личность, институциональная подпись или решение DAC, система готовит конкретный пакет и показывает, чьё действие необходимо. Уже разрешённые штатные запросы выполняются автоматически в заданных пределах.

Голосовой канал — последующее дополнение: распознавание превращает речь в текст той же миссии, показывается подтверждаемая транскрипция и доступна текстовая альтернатива. Он не расширяет права. Для разработчика доступны API и ограниченный MCP; для длительных работ нужен работающий daemon и постоянное хранение. Закрытие вкладки не должно останавливать очередь, а перезапуск сервера должен восстанавливать её.

Практический результат первой ступени — воспроизводимая исследовательская работа: карта источников, проверенный вычислительный артефакт, журнал и ограничения. Изменение взрослого организма, появление новых органов или увеличение интеллекта не являются подтверждённой возможностью объединённых программ и требуют самостоятельного научного подтверждения. Сетевой масштаб не снимает этот пробел.
