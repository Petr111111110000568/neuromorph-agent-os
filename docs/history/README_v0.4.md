# Meta-Harness v0.4 · Research Workbench

Рабочая локальная веб-консоль для систематизации источников и воспроизводимых вычислительных экспериментов. Восстановлена из сохранённого SRF v0.3 и дополнена отдельным backend, SQLite, MCP stdio, журналом и тестами. Русский интерфейс; Python 3.11+; ядро не требует pip-пакетов.

## Запуск

Распакуйте весь архив. На Windows запустите `start.cmd` (нужен Python 3.11+). На Linux/macOS:

```bash
cd Meta-Harness-v0.4
python3 -m workbench serve
```

Откройте `http://127.0.0.1:8765`. Остановка — Ctrl+C. Не открывайте `web/index.html` напрямую: интерфейсу нужен API.

Для отдельного окружения, без скачивания научных пакетов:

```bash
python3 scripts/bootstrap.py
```

Проверка:

```bash
python3 -m workbench doctor
python3 -m unittest discover -s tests -v
python3 -m workbench run quantum_circuit --parameters '{"theta":0,"shots":100}'
```

В Windows для JSON в командной строке удобнее использовать интерфейс приложения. Ядро проверено в Linux/Python 3.12; Windows/macOS в этой среде не запускались.

## Что работает

- Реестр изученных первичных источников и добавление своих записей.
- Восемь ролей локального совета: структурированная проверка по правилам.
- Четыре встроенных модуля: связанные динамические системы, ML holdout-бенчмарк, двухкубитная CPU-симуляция, проверка контракта топологии.
- Цикл вопрос → совет → вычисление → сохранённый отчёт с ограничениями.
- База SQLite, сохранение параметров и версий кода, хеш-цепочка событий.
- Экспорт JSON и Markdown; ограниченный MCP stdio-профиль.

Совет правил не является встроенным коллективом LLM. Ключей моделей, удалённого GPU, QPU и постоянного сервера в сборке нет. Настройка этих сервисов не возникает из подписки ChatGPT.

## MCP

```bash
python3 -m workbench mcp
```

Процесс использует stdin/stdout JSON-RPC; сообщения диагностики не смешиваются с протоколом. Профиль: lifecycle + tools для исследовательских операций, версия 2025-11-25. Текущая спецификация MCP может иметь дополнительные возможности; полной совместимости с ней не заявлено. Для hosted Work нужен устанавливаемый плагин/поддерживаемый сервер; локальный config.toml в scratch не подключает инструменты к аккаунту.

## Научная область применения

Демонстрационные расчёты проверяют код и математические модели. Они не прогнозируют исходы редактирования человека, не создают синтетические геномы и не доказывают возможность ускоренной эволюции взрослого организма. Требуется отдельная научная валидация узких моделей на данных.

Старый `srf/` сохранён для совместимости и анализа. Его интерфейсные заглушки и фиксированные эвристические оценки не равны готовым научным интеграциям. См. `docs/WEB_ARCHITECTURE_RU.md`.

## Документы

- `docs/OPENAI_WORK_RU.md` — проверенные возможности OpenAI, Work/Codex/API и ограничения аккаунта.
- `docs/RESEARCH_LANDSCAPE_RU.md` — автономные исследования, генетика/эпигенетика, источники и выбранные модули.
- `docs/QUANTUM_AGENTS_RU.md` — квантовые пакеты, агентные системы, MCP и изоляция.
- `docs/WEB_ARCHITECTURE_RU.md` — варианты размещения и границы веб-приложения.
- `docs/VALIDATION_RU.md` — итоговые выполненные проверки.
- `data/environment_status.json` — снимок состояния окружения на дату подготовки, не автоматическое обещание текущего доступа.

`configs/optional_workers.json` — план внешних подключений, не установщик. `configs/runtime.json` — декларация профиля; фактические настройки запуска задаёт CLI. Тяжёлые зависимости следует разрешать и фиксировать отдельно для каждого worker.

## Хранение и перенос

Рабочая SQLite создаётся в `state/workbench.sqlite3` внутри папки проекта. Другой каталог задаётся перед подкомандой: `python3 -m workbench --data-dir /путь/к/данным serve`. Для переноса остановите приложение и скопируйте весь каталог состояния либо используйте экспорт для отчёта. JSON-экспорт предназначен для просмотра/архивирования; импорт базы в этой версии не реализован. Архив исходников намеренно не включает рабочую базу, виртуальное окружение и секреты.

Сборка архива: `python3 scripts/package.py`. Рядом создаётся SHA256; внутри — BUILD_MANIFEST.json. Доверенные хеши builtin-плагинов находятся в data/builtin_pins.json. Любая смена исходников плагина требует проверки и сознательного обновления этого файла; приложение не доверяет изменённому коду автоматически.

## Ограничения эксплуатации

Сервер слушает только localhost; это однопользовательский инструмент, не готовый многопользовательский интернет-сервис. На POSIX дочерний процесс ограничен по CPU, памяти и размеру результата; это не защита от недоверенного кода. Хеш-цепочка обнаруживает частичные изменения журнала, но без внешней подписи не защищает от полного переписывания.

Оригинальные материалы пользователя не публикуются. Новое видео зарегистрировано по метаданным; его содержание не расшифровано и не принято как научное доказательство. Внешние проекты из обзора имеют статус изученных, а не установленных.
