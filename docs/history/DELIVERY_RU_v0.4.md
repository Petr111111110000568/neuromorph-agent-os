# Meta-Harness v0.4: результат настройки и исследовательская архитектура

18 сентября 2026 года

Подготовлена работающая локальная веб-консоль для источников, совета исследовательских ролей и воспроизводимых расчётов. Установлен личный навык работы с проектом в ChatGPT Work. Полная автономная лаборатория и система управляемого изменения взрослого организма не созданы: это отдельные научные и инфраструктурные задачи, готовность которых текущие проверки не подтверждают.

## Фактические изменения

| Область | Сделано | Точная граница |
|---|---|---|
| Аккаунт Work | Установлен и проверен навык [meta-harness-research](https://chatgpt.com/skills?skill_id=6aad8623cbb88191898d2419ddee18e1) | Организует восстановление проекта, совет, доказательства, вычисления и выпуск результатов; не выдаёт API-ключи |
| Подключения | Успешно проверены существующие GitHub и Context7 | Проверка чтения; публичные репозитории не изменялись |
| Окружение проекта | Python venv, инструкции проекта, диагностика, запуск и упаковка | Ядро без обязательных внешних пакетов; venv пересоздаётся, а не переносится в архиве |
| Веб-приложение | 7 разделов, HTTP API, SQLite, динамические формы, графики и экспорт | Локальная однопользовательская версия на 127.0.0.1 |
| Совет | 8 ролей, вопрос и явно выбранные источники | В приложении это правила; в сеансе Work исследование выполнялось реальными параллельными агентами |
| Модули | Динамические системы, ML-бенчмарк, двухкубитная симуляция, проверка топологии | Математические демонстрации; не модели целого человека |
| Совместимость | MCP stdio: жизненный цикл и инструменты, профиль 2025-11-25 | Это ограниченный профиль, не полная поддержка новейшей спецификации |
| Доказательства | 45 изученных первичных источников, происхождение результатов, хеши кода и журнал | Ссылка или успешный расчёт не означают научной валидации |

API-провайдер для нового приложения, GPU/QPU, постоянный сервер, внешняя очередь и лабораторные устройства не подключены. Общие параметры тарифа, модели, биллинга и безопасности аккаунта не изменялись. Непрерывное недельное исполнение и расписание фоновых запусков не включены.

## Что установлено по документации OpenAI

Текущий помощник работает как Codex в Work: доступные инструменты позволяют исследовать, писать код, выполнять проверки и делегировать независимые задания. Точное имя внутренней модели и административные права аккаунта нельзя надёжно определить из текста ответов.

Настройки hosted Work, локального Codex и собственного API-приложения различаются. Браузерный Work не получает MCP из произвольного `config.toml`, созданного в рабочей папке; подключение осуществляется поддерживаемыми плагинами. Поэтому вместо фиктивной глобальной конфигурации установлен реальный личный навык и проверены имеющиеся подключения. [Официальная документация MCP](https://learn.chatgpt.com/docs/extend/mcp).

Длительная работа требует сохранения состояния за пределами временной рабочей папки. Задачи по расписанию не гарантируют перенос локального каталога между запусками. В поставке есть сохранение завершённых расчётов и возможность восстановления проекта; постоянный планировщик предстоит развернуть отдельно. [Scheduled tasks](https://learn.chatgpt.com/docs/automations).

Rosalind Workbench — особенно близкий ориентир: исследовательская среда для наук о жизни с инструментами и направляемыми задачами. Доступ текущего аккаунта к ней не подтверждён; поиск доступных плагинов не дал соответствующего подключения. [Rosalind Workbench](https://developers.openai.com/blog/rosalind-workbench).

## Выбор архитектуры и передовых компонентов

Подходит веб-приложение с отдельными вычислительными исполнителями. Браузер хранит состояние представления; сервер отвечает за данные, права и задания; научные пакеты запускаются в подходящих им окружениях. Это позволяет независимо менять UI, агентную систему, модели и оборудование.

Порядок интеграции ниже — наше инженерное решение по результатам обзора, а не доказанная авторами совместимость всех проектов.

| Этап | Компонент | Проверяемый результат подключения |
|---|---|---|
| 1 | [ToolUniverse](https://github.com/mims-harvard/ToolUniverse) | Ограниченный каталог научных инструментов; реальные вызовы выбранных средств поиска и анализа |
| 2 | Nextflow и один nf-core workflow | Воспроизводимое выполнение официального тестового набора и восстановление после прерывания |
| 3 | [scvi-tools](https://github.com/scverse/scvi-tools) | Анализ публичных single-cell данных с простым baseline и независимой оценкой |
| 4 | [AlphaGenome](https://github.com/google-deepmind/alphagenome) | Узкая исследовательская оценка регуляторных эффектов при проверенном API-доступе |
| 5 | [Paper2Agent](https://www.nature.com/articles/s41586-026-11044-y) | Превращение выбранного метода статьи в проверенный инструмент с контрольным примером |
| 6 | Biomni, Evo 2, PhysiCell | Отдельные предметные исполнители с фиксированными зависимостями, данными и критериями валидации |
| 7 | Qiskit / PennyLane / Cirq / QuTiP | Классический контроль, симуляция и измеримая задача до отдельного рассмотрения QPU |

Paper2Agent особенно полезен для идеи «всё подключается модулем»: статья описывает создание интерактивных агентов вокруг исследовательских программ. Но адаптер и тесты не устраняют ошибки или ограничения самой научной работы. [Первичная публикация](https://www.nature.com/articles/s41586-026-11044-y).

Для каждого модуля нужны версия кода, лицензия и условия весов/данных, входы и выходы, ресурсы, доступ к сети, отмена, контрольный набор и ожидаемая погрешность. Внешние пакеты в обзоре изучены, но ещё не установлены в работающий комплекс.

Sites можно рассматривать для интерфейса и открытых/синтетических данных. Документированные ограничения по PHI и фоновым службам требуют отдельной инфраструктуры для персональной геномики и длительных вычислений. Публичное размещение не выполнено. [Документация Sites](https://learn.chatgpt.com/docs/sites).

## Запуск поставки

Распакуйте `Meta-Harness-v0.4.zip`. Установленный Python должен быть версии 3.11 или новее. В каталоге `Meta-Harness-v0.4` выполните:

```bash
python3 -m workbench serve
```

Откройте `http://127.0.0.1:8765`. Windows: запустите `start.cmd`. Для отдельного окружения предусмотрен `python3 scripts/bootstrap.py`; скачивание тяжёлых пакетов для ядра не требуется.

Обычный сценарий: зарегистрировать источник → выбрать вопрос и связанные записи → выполнить модуль → просмотреть расчёт и ограничения → экспортировать JSON/Markdown. База создаётся в `state/workbench.sqlite3`; JSON-экспорт не является форматом восстановления базы в этой версии.

## Проверка результата

21 автоматический тест прошёл. Отдельный HTTP-сценарий подтвердил выдачу файлов интерфейса, запуск реального вычислительного процесса с выбранным источником, экспорт и сохранность после перезапуска базы. Проверены синтаксис JS и соответствие статических HTML-ссылок.

Визуальная и интерактивная браузерная проверка не выполнена: управляемый браузер среды отклонил localhost с `net::ERR_BLOCKED_BY_CLIENT`. Windows/macOS и постоянный интернет-сервер здесь не испытывались. Ограничения процессов не составляют полноценную песочницу для стороннего кода.

Подробности и воспроизводимые команды: `docs/VALIDATION_RU.md`, `tests/`, `scripts/smoke_release.py`. Обзоры: `docs/OPENAI_WORK_RU.md`, `docs/RESEARCH_LANDSCAPE_RU.md`, `docs/QUANTUM_AGENTS_RU.md`. Архитектура: `docs/WEB_ARCHITECTURE_RU.md`.

Достижение биологической цели остаётся неподтверждённым. Успех программных тестов говорит о работе программы и контрольных математических примеров; он не подтверждает безопасность, жизнеспособность или эффективность изменений взрослого организма.
