# Meta-Harness v0.5 · Распределённая исследовательская сеть

Веб-приложение, координатор и независимые исполнители для сбора научных метаданных, систематизации ресурсов и воспроизводимых вычислительных проверок. Продолжение v0.4. Python 3.11+, стандартная библиотека; научные пакеты для ядра не нужны.

## Быстрый запуск

Распакуйте весь архив. Windows с установленным Python: `start.cmd`. Linux/macOS:

```bash
cd Meta-Harness-v0.5
python3 -m workbench local-network
```

Откройте `http://127.0.0.1:8765/network.html`. Команда запускает UI, координатор, авторизованный hub и **два отдельных worker-процесса**. Временный секрет создаётся автоматически, не выводится и не записывается в базу. Ctrl+C останавливает компоненты. Задачи и результаты сохраняются в `state/`.

Для другого каталога состояния:

```bash
python3 -m workbench --data-dir ./research-state local-network --workers 2
```

Это распределённый протокол в локальной топологии. Для физически разных компьютеров предусмотрен HTTPS-режим: отдельные hub, daemon и workers. Инструкция — `docs/NETWORK_DEPLOY_RU.md`. Работа на нескольких физических машинах здесь не испытывалась. SQLite находится на локальном диске координатора, не на общем сетевом диске. Все процессы координатора должны использовать один каталог состояния; у workers свои каталоги.

## Рабочий сценарий

1. Ввести исследовательский вопрос и получить объяснимый план сопоставления ресурсов.
2. Найти публикации через реальные публичные API Europe PMC и Crossref либо искать только в локальном каталоге.
3. Запустить ограниченную кампанию: поиск → методический контрольный расчёт → сбор результатов → обновление каталога и плана → следующий запрос → остановка по бюджету.
4. Просматривать исполнителей, попытки и результаты; отменять задания и кампании.
5. Инвентаризировать выбранный локальный каталог по именам, типам и размерам файлов без чтения содержимого и исполнения кода.
6. Вести профили сервисов, способы доступа, scopes и заявки на подключение.
7. Экспортировать состояние и происхождение результатов без bearer/lease-токенов.

На старте каталог содержит **60 записей**: 46 исходных источников/материалов и 14 описаний возможностей. Четыре адаптера реально исполняют встроенные математические примеры. Другие научные платформы представлены как внешние ресурсы без работающего адаптера.

Страница `/` сохраняет v0.4: восемь советников по правилам, источники, четыре модуля, графики и журнал. Новые операции доступны через расширенный MCP stdio: `python3 -m workbench mcp`. Это ограниченный профиль протокола 2025-11-25.

## Автономность и восстановление

Пока работает `local-network` или отдельный `daemon`, кампании продвигаются независимо от открытой вкладки. Пределы: 1–5 итераций, 1–20 логических заданий; до двух попыток на задание кампании. На итерацию приходится поиск и, при включении, один синтетический расчёт. Запросы уточняются правилами: валидация, ограничения, воспроизводимость, отрицательные результаты.

Планировщик использует слова и тематические возможности; это не LLM и не доказанно оптимальный алгоритм. Флаг `online` разрешает отправку поискового запроса публичным провайдерам; по умолчанию в кампании он выключен. Полные тексты статей автоматически не читаются.

Задания имеют аренду, heartbeat, лимит попыток и защиту от запоздалого результата. После сбоя вычисление может повториться: гарантия не менее одного раза. Идемпотентные ключи предотвращают дублирование логических заданий. Отмена восстанавливает связь даже с заданием, отправленным перед прерыванием записи кампании.

## Аккаунты и подключение ресурсов

Реализованные публичные API метаданных работают без регистрации — это проверено. Для других сервисов профиль хранит **имя** переменной окружения с credentials, scopes и URL настройки. Значение секрета через UI не принимается. Наличие переменной не означает успешную внешнюю авторизацию.

Заявка получает `no_registration_required` или `requires_user_action`. Универсального создания аккаунтов, прохождения OAuth/CAPTCHA, принятия условий и покупки доступа нет. Конкретные API регистрации требуют отдельных проверенных адаптеров. См. `docs/ACCOUNTS_RU.md`.

Найденные сайты, модели и репозитории не скачиваются и не исполняются автоматически. Метаданные не подтверждают доступ или совместимость. Worker исполняет только поиск метаданных и закреплённые встроенные вычисления.

## Биологическая область применения

Запрос «сформировать признаки во взрослом организме» преобразуется в поиск доказательств, сопоставление моделей и оценку недостающих данных. Система не выдаёт план вмешательства, не генерирует модифицированный геном и не прогнозирует появление органов или безопасность изменения человека.

Геномика, эпигеномика, клеточные и тканевые модели представлены в каталоге с ограничениями. Исполняемые интеграции AlphaGenome/scvi-tools/nf-core/PhysiCell здесь не подключены. Синтетический ML-контроль и двухкубитная CPU-симуляция проверяют вычислительный путь, а не желаемые признаки организма.


## Документы и эксплуатация

- `NETWORK_CONTRACT.md` — API сети; `CONTRACT.md` — основного приложения.
- `docs/NETWORK_DEPLOY_RU.md` — многомашинное размещение и протокол.
- `docs/DISCOVERY_RU.md` — провайдеры, ранжирование, лимиты и первичные источники.
- `docs/ACCOUNTS_RU.md` — профили и заявки доступа.
- `docs/DELIVERY_RU.md` — фактический результат v0.5.
- `docs/history/` — отчёты v0.4, исторические статусы.

Общий токен объединяет доверенных workers, но не разделяет пользователей/организации. TLS не изолирует вычисления. Процессы и лимиты не заменяют контейнер/VM для чужого кода. База не шифруется приложением. Для многопользовательской облачной эксплуатации нужна отдельная инфраструктура.

Для резервной копии остановите компоненты и скопируйте весь каталог состояния. JSON-экспорт предназначен для анализа/архива; импорта базы из него нет. Исходный ZIP исключает `state`, venv, базы и секреты. Сборка: `python3 scripts/package.py`; хеши встроенного кода — `data/builtin_pins.json`.
