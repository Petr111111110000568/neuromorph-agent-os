# Квантовые вычисления и оркестрация агентов для Meta-Harness

Проверка первичных источников: **18 сентября 2026 года**. Это инженерная рекомендация и реестр проверенных источников, а не отчёт об установке перечисленных SDK. Доступность программного пакета не означает наличие QPU, лабораторного оборудования или доказанной способности изменять взрослый организм.

## Решение для первой рабочей версии

**Веб-приложение с серверными вычислительными плагинами подходит проекту.** Браузер показывает гипотезы, доказательства, задачи, бюджет, состояние вычислений и результаты. На сервере отдельный оркестратор сохраняет состояние задач, назначает роли советников и вызывает плагины. Квантовый модуль является необязательной вычислительной ветвью: базовые исследования, поиск литературы и классическое моделирование должны работать без него.

Инженерный выбор: один основной механизм управления задачами; для первого расширения — LangGraph, либо существующий проверенный планировщик проекта. Другие агентные системы подключать отдельными сервисами с ограниченным набором возможностей. Несколько вложенных оркестраторов без общего учёта бюджета, состояния и отмены затруднят воспроизводимость.

На просмотренной странице IBM примеры заявлены для `qiskit[all]~=2.5.2`, `qiskit-ibm-runtime~=0.47.0`, `qiskit-aer~=0.17`. Документация PennyLane обозначена как 0.45.1, QuTiP — 5.3. Это снимок документации, **не проверенный совместный lock-файл**. У QuTiP часть страницы установки содержит исторические ограничения; фактическую совместимость следует разрешать по метаданным выбранного релиза и фиксировать после тестов.

### Классический симулятор и QPU

Полный вектор состояния из `n` кубитов содержит `2^n` комплексных амплитуд. При complex128 только амплитуды для 30 кубитов занимают 16 GiB; это математическая оценка без памяти на промежуточные операции. Матрица плотности масштабируется как `4^n`. Специальные стабилизаторные и тензорные методы могут быть значительно экономнее на подходящих классах схем; IBM прямо различает эти методы в документации Aer.

Рекомендуемый порядок исполнения: точная классическая база → классический симулятор схем → шумовая симуляция → отдельная проверка QPU. Сравнивать качество, доверительные интервалы, время целиком, память, число запусков, стоимость и ошибки. Для результатов хранить backend, seed, shots, версию схемы и SDK, калибровку устройства при наличии, хеш входных данных. **В проверенных здесь источниках нет основания обещать квантовое ускорение геномного проектирования или безопасного преобразования взрослого организма.**

| Инструменты и данные | [MCP 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28) | JSON-RPC-контракт между host/client/server; tools, resources, prompts. Текущие Tasks, Skills over MCP и MCP Apps — дополнительные возможности, требующие явной поддержки обеих сторон. |
| Процедуры | [Agent Skills](https://agentskills.io/home) | Версионируемые папки с `SKILL.md`, инструкциями и ресурсами; последовательная загрузка по необходимости. Skill описывает работу, но сам не предоставляет CPU, сеть, полномочия или изоляцию. |

**MCP — транспорт и соглашение об интерфейсе; оркестратор — исполняющая система.** Ни MCP, ни папка skill не превращают произвольный репозиторий в совместимый плагин автоматически. Для проекта нужны манифест, адаптер входа/выхода, проверка схем, доступные ресурсы и тест соответствия. Не следует молча менять версию протокола уже работающего сервера: сопоставить поддерживаемую клиентом версию, SDK и конкретный профиль транспорта.

Практические предлагаемые контракты модулей:

- `quantum.simulate`: ограниченная декларативная схема, backend, seed, shots → измерения, неопределённость и provenance.
- `quantum.resources`: схема и метод симуляции → оценка памяти/вычислений, допустимость запуска.
- `physics.open_system`: проверяемая модель и численные параметры → динамика наблюдаемых и диагностика решателя.
- `benchmark.compare`: общий набор задач и метрики → сопоставление классического, симуляционного и аппаратного результатов.
- `harness.run / status / cancel`: идентификатор плана, лимиты и входные артефакты → сохранённое состояние и артефакты результата.

Это проектные контракты, а не заявление, что перечисленные плагины уже реализованы.

## Что взять из автономных лабораторий

[A-Lab](https://www.nature.com/articles/s41586-023-06734-w) демонстрирует замкнутый цикл для ограниченного класса неорганических материалов: исходные данные, модель, автоматизированное измерение и обновление решения. Статья опубликована в 2023 году и исправлена 19 января 2026 года. В текущем тексте указаны **36 успешных целей из 57 за 17 дней**, 353 эксперимента; четыре дополнительных результата признаны неоднозначными при повторном анализе. Использовать актуальные числа, а не старую рекламную сводку.

Переносимый урок для Meta-Harness — сохранять исходные измерения, отделять автоматическое заключение от повторной проверки и корректировать знания при новых данных. Программная интеграция литературного поиска с агентами сама по себе не воспроизводит физическую лабораторию. Для проекта первой очереди пригоден вычислительный замкнутый цикл: гипотеза → имеющиеся данные → расчёт → сравнение с заранее заданной метрикой → пересмотр гипотезы. Аппаратные лабораторные модули требуют собственных драйверов, калибровки и проверок.

## Граница исполнения плагина

[Docker](https://docs.docker.com/engine/security/) использует namespaces, cgroups и возможности ядра; доступ к Docker daemon потенциально даёт существенные права на хосте. Поэтому вычислитель запускается без Docker socket, привилегированного режима и широких host mounts; с отдельной рабочей папкой, ограничениями CPU/RAM/времени, read-only образом и заданным сетевым доступом.

Для неизвестного кода или взаимно недоверяющих плагинов предпочтительна отдельная VM/microVM. [Firecracker](https://firecracker-microvm.github.io/) предоставляет KVM-границу и jailer; нужен Linux-хост с аппаратной виртуализацией и доступом к KVM. Это инфраструктура развёртывания, её нельзя получить простым `pip install` в браузере или текущем контейнере. Контейнер не эквивалентен Qubes-домену; ни одна из этих мер сама по себе не заменяет управление секретами и сетевыми правами.

## Уровни доказательств и нетрадиционные гипотезы

Для любой идеи, включая лингвистико-волновые и микролептонные гипотезы, сохранять точное утверждение, первоисточник, измеряемое предсказание, данные, независимые проверки и возможные опровержения. Статусы предлагаются такие: `hypothesis`, `simulation_only`, `observed`, `independently_replicated`, `disputed`, `unsupported_in_reviewed_sources`. Это статусы конкретного утверждения, а не характеристика автора.

Расчёт волновой функции в QuTiP или успешное обучение PennyLane не подтверждает связь словесных команд с изменением генома: это иной проверяемый тезис. Корреляция, модель и воспроизведённое причинное воздействие должны иметь разные поля. Веб-приложение может сопоставлять эти идеи на общих критериях доказательности, не объявляя заранее доказанным то, для чего нет независимых подтверждений.

## Очерёдность подключения

1. Сначала надёжный реестр источников, версия данных, очередь задач, сохранение состояния и артефактов, воспроизводимые классические расчёты.
2. Затем один симулятор квантовых схем и QuTiP в отдельных окружениях; аналитические контрольные примеры и лимит размера задачи.
3. Затем PennyLane/Cirq только под конкретный бенчмарк либо совместимость с нужным исследованием.
4. QPU после проверенного доступа, бюджета и измеримого основания ожидать пользу. Автоматическое приобретение доступа и передача исследовательских данных не входят в этот обзор.
5. Внешний harness подключать после тестов отмены, перезапуска, лимитов и сохранения происхождения результатов.

Машиночитаемый реестр из 12 источников: `data/quantum_sources.json`. Значение `reviewed_not_installed` означает просмотр документации, а не успешное развёртывание.
