# Подключение реальных научных ресурсов и платформ сотрудничества

Проверено **18 сентября 2026 года**. Этот документ дополняет каталог научных агентов практическими точками подключения. В ходе проверки выполнены **пять публичных HTTP GET к Hugging Face Hub без авторизации**; все вернули HTTP 200. Прочитаны только метаданные. Веса моделей, экспериментальные наборы, сторонний исполняемый код и платные вычисления не загружались и не запускались.

## Что можно задействовать прямо сейчас

Первый полезный коннектор — **поиск моделей, наборов данных и Spaces через открытый Hugging Face Hub API**. Он даёт системе доступ к реальному внешнему каталогу, сведениям о происхождении, версии, лицензии и ограничениях ресурса. Найденный ресурс затем проходит отдельную проверку пригодности. Документированный поиск поддерживается как HTTP API, так и официальными Python/JavaScript-клиентами. [Hub API](https://huggingface.co/docs/hub/main/api), [поиск](https://huggingface.co/docs/huggingface_hub/en/guides/search)

Это реальное использование общего научно-технического ресурса, однако **получение карточки не является общением с самостоятельным исследовательским агентом**. Модель, Space, benchmark, очередь вычислений и агентный протокол — разные сущности.

| Платформа | Кто предоставляет | Роль в Meta-Harness | Доступ и текущая граница |
|---|---|---|---|
| Hugging Face Hub | Hugging Face; содержимое публикуют отдельные авторы | Обнаружение моделей, данных, кода и связанных публикаций | Проверены публичные GET без ключа; ресурс не считается проверенным только по карточке |
| Hugging Face Spaces | Hugging Face и владельцы Spaces | Обнаружение демонстраций и потенциальных API/MCP-сервисов | Поиск проверен; доступность работающего приложения и право его вызова проверяются отдельно |
| Hugging Face Jobs | Hugging Face | Управляемое исполнение заранее подготовленных вычислительных заданий | Требуются собственная авторизация и положительный кредитный баланс; не запущено |
| ScienceAgentBench | OSU NLP Group и исследовательские соавторы | Объективные задания для оценки исполнителей | Есть публичные входные аннотации; полноценная оценка использует отдельные эталонные артефакты |
| Agent Laboratory / AgentRxiv | Разработчики Agent Laboratory; AgentRxiv — Samuel Schmidgall и Michael Moor | Образец обмена накопленными результатами между исследовательскими процессами | Открытый код и авторские эксперименты; общедоступная постоянно работающая сеть с проверенным API не установлена |
| BOINC / Science United | Независимые BOINC-проекты; Science United — проект BOINC в UC Berkeley | Добровольные распределённые вычисления и распределение ресурсов по областям науки | Это вычислительная инфраструктура; участие не предоставляет автоматически мощности для нашей произвольной задачи |
| Gensyn RL Swarm | Gensyn | Открытая архитектура совместного RL между узлами | **Официальные swarms приостановлены**; собственный/community swarm — отдельное развёртывание |

Источники для таблицы: [HF Spaces](https://huggingface.co/docs/hub/spaces-overview), [HF Jobs](https://huggingface.co/docs/huggingface_hub/en/guides/jobs), [ScienceAgentBench](https://github.com/OSU-NLP-Group/ScienceAgentBench), [AgentRxiv](https://agentrxiv.github.io/), [Science United](https://scienceunited.org/), [Gensyn status](https://docs.gensyn.ai/testnet).

## Проверенный контракт публичного HF-коннектора

**Поставщик:** Hugging Face. **Разрешённый host:** `huggingface.co`. **Схема:** HTTPS. **Метод:** GET. На первом этапе авторизация не используется.

| Назначение | Путь и параметры | Проверенный ответ |
|---|---|---|
| Поиск моделей | `/api/models?search=scGPT&limit=3&cardData=true` | JSON array, 3 записи |
| Поиск наборов | `/api/datasets?search=ScienceAgentBench&limit=3&full=true` | JSON array, 3 записи |
| Карточка набора | `/api/datasets/osunlp/ScienceAgentBench` | JSON object с revision и cardData |
| Карточка модели | `/api/models/microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract-fulltext` | JSON object с revision и cardData |
| Поиск Spaces | `/api/spaces?search=Paper2Agent&limit=3` | JSON array, 3 записи |

Общий шаблон запроса поиска:

```json
{
  "provider": "huggingface",
  "resource_type": "dataset",
  "query": "ScienceAgentBench",
  "limit": 3
}
```

Параметры кодируются стандартным URL encoder. Пользователь задаёт текст поиска и тип ресурса, а не произвольный сетевой URL. Типы для первого адаптера: `model`, `dataset`, `space`. Схемы HTTP-ответов расширяемы: незнакомые поля можно игнорировать, необходимые поля валидировать, отсутствующие значения сохранять как неизвестные.

**Поля нормализованной карточки:**

- `provider`, `resource_type`, `id`, `namespace`;
- `canonical_url`, точный `fetched_url`, `checked_at`;
- `revision_sha`, если получен;
- `private`, `gated`, `disabled` — трёхзначное состояние true/false/unknown;
- `license_declared`, `license_name`, `license_link`, источник лицензионного поля;
- `tags`, `pipeline_tag` или `sdk`;
- `upstream_claims` отдельно от собственных результатов проверки;
- `availability_status=metadata_observed`;
- `execution_status=not_executed`.

Поле `cardData.license` — заявление автора карточки. Оно не распространяет разрешение на все зависимости, исходные данные и базовые модели. Если поля нет, значение **unknown**, а не «свободно использовать». Ссылки `license_link`, текст карточки и теги не исполняются как инструкции. Официальное описание формата объясняет роль карточек и метаданных. [Model Cards](https://huggingface.co/docs/hub/model-cards)

**Наблюдённые конкретные записи:**

| Ресурс | Snapshot, полученный без ключа | Практическое значение |
|---|---|---|
| `osunlp/ScienceAgentBench` | revision `9c6e96c9e74572e979b0930ee735041cef528cb7`; `private=false`, `gated=false`; карточка `cc-by-4.0`; split `verified`, 102 примера | Официальная запись входных аннотаций benchmark; лицензии отдельных задач проверяются дополнительно |
| `microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract-fulltext` | revision `e1354b7a3a09615f6aba48dfad4b7a613eef7062`; `private=false`, `gated=false`; карточка `mit`; pipeline `fill-mask` | Пример реальной модели, а не самостоятельного агента; пригодность для цели не оценивалась |
| `Paper2Agent/alphagenome_agent` | `private=false`, SDK `static` | Наличие Space не доказывает работающий вычислительный backend |
| `Paper2Agent/alphagenome_mcp`, `Paper2Agent/tissue_mcp` | `private=false`, SDK `docker` | Кандидаты для дальнейшей проверки интерфейса; MCP-вызовы не выполнялись |

Поиск ScienceAgentBench также вернул копии других авторов. Поэтому одинаковое название не заменяет проверку namespace и ссылки из первичного репозитория. Счётчики скачиваний и likes не используются как доказательство качества.

Для адаптера рекомендуется: ограниченный размер ответа и timeout; предельное число записей; обработка 429 с ограниченным повтором; кэширование; запрет автоматического перехода на произвольный host; чтение JSON без выполнения кода. При пустом ответе не подменять его выдуманными ресурсами. Это проектные требования; отдельные сценарии ошибок в рамках данного исследования не проверялись.

## ScienceAgentBench как общая мера результатов

ScienceAgentBench содержит 102 задачи из 44 опубликованных работ разных дисциплин. Агенты должны выдавать исполняемый Python-артефакт; затем измеряются выполнение и результат. В апреле 2026 авторы выпустили `verified`-версию для уменьшения ложных отрицательных оценок. Следует использовать её вместе с соответствующими артефактами. [Официальный репозиторий](https://github.com/OSU-NLP-Group/ScienceAgentBench), [карточка](https://huggingface.co/datasets/osunlp/ScienceAgentBench)

Для Meta-Harness это полезнее рейтинга на основе впечатления от текста:

1. выбрать небольшой открыто описанный набор подходящих задач;
2. закрепить версию и условия оценки;
3. дать задания разным разрешённым исполнителям с одинаковым бюджетом;
4. оценить артефакты независимым проверяющим;
5. сохранить успешные и неуспешные попытки;
6. использовать результат только для соответствующего класса задач.

Код benchmark и материалы задач имеют разные лицензионные условия; в карточке явно указаны исключения. Эталонные файлы не следует выкладывать в общий обменный архив: авторы просят не распространять распакованные материалы, в том числе ради предотвращения загрязнения benchmark. Модель не должна получать эталонный ответ через общий индекс результатов.

## AgentRxiv: полезный пример сотрудничества, требующий собственной проверки

AgentRxiv описывает общий архив, через который независимые процессы Agent Laboratory публикуют результаты и находят предыдущую работу. Авторы демонстрируют три параллельные лаборатории, изучающие вычислительную задачу и использующие взаимные результаты. Это близко к требованию накопительного сотрудничества. [Авторская страница AgentRxiv](https://agentrxiv.github.io/)

Однако эксперимент на языковых/математических benchmarks не подтверждает биологического прогресса. Доказательства постоянно доступного публичного API, к которому мы уже можем присоединить учётную запись, здесь не получены. [Agent Laboratory](https://github.com/SamuelSchmidgall/AgentLaboratory) — открытый framework, который можно отдельно оценивать и разворачивать.

Практический перенос в Meta-Harness: обменивать не только рукописи, а **пакеты результатов** — вопрос, код, версии, входные данные или разрешённые ссылки, метрики, ошибки, ограничения и подпись узла. Повторная проверка чужого пакета создаёт новую запись, связанную с исходной, и не переписывает её. Такая архитектура позволяет измерить, помогает ли обмен результатами по сравнению с изолированными агентами.

## BOINC и Science United

BOINC-проекты независимы: у каждого свои серверы, задания и правила участия. Science United распределяет добровольно предоставленные ресурсы между одобренными проектами по выбранным научным областям. Это реальное распределённое исполнение, но не общий свободный суперкомпьютер для любых запросов пользователя. [Выбор проектов BOINC](https://github.com/BOINC/boinc/wiki/Choosing-and-joining-projects), [Science United](https://scienceunited.org/intro.php)

Для собственной кампании Meta-Harness необходимо либо сотрудничество с соответствующим проектом, либо собственный сервер заданий и добровольные участники с согласованной политикой. Подключение к существующему проекту означает предоставление ему ресурсов; право перенаправить ресурсы остальных участников к нашей цели из этого не возникает.

Целесообразно заимствовать принципы: версионирование задач, учёт аппаратных возможностей, независимая проверка результатов, справедливое распределение ресурсов и возможность участника ограничить нагрузку. Подключение клиента с запуском чужих заданий не выполнялось.

## Gensyn: архитектура доступна, официальный RL Swarm сейчас приостановлен

Верхнеуровневая документация и актуальное предупреждение README прямо сообщают, что официальных RL Swarm сейчас нет. На некоторых нижних разделах сохранился текст о «текущем» CodeZero; приоритет имеет явное сообщение о паузе. [Состояние testnet](https://docs.gensyn.ai/testnet), [RL Swarm](https://docs.gensyn.ai/testnet/rl-swarm), [репозиторий](https://github.com/gensyn-ai/rl-swarm)

Открытый framework остаётся кандидатом для собственного исследования совместного RL. Наличие blockchain-идентичности и записанного вклада не доказывает научную истинность результата. Создание собственного swarm потребует вычислителей, выбранной задачи, моделей, проверки лицензий и отдельного benchmark. Не следует обещать немедленное включение в действующий официальный swarm по старой инструкции.

## Как появятся реальные внешние вычисления

Hugging Face Jobs документирует запуск заданий на инфраструктуре провайдера: пользователь авторизуется в своём HF-аккаунте, выбирает образ, команду и ресурсы, а сервис возвращает идентификатор задания, статус и журналы. Требуется положительный кредитный баланс. [Jobs](https://huggingface.co/docs/huggingface_hub/en/guides/jobs)

Собственный ограниченный token и бюджет позволяют позднее подключить такой backend. Подписка ChatGPT сама по себе не создаёт HF-token, HF-кредиты или право на чужой вычислитель. Секреты передаются через предназначенное для них хранилище; они не входят в общий каталог, отчёт или сообщения между агентами.

У Spaces также есть условия доступа: актуальная обзорная страница различает бесплатные Static Spaces и требования плана для создания Gradio/Docker Spaces, с отдельным исключением для ограниченного ZeroGPU-размещения подходящих бесплатных аккаунтов. Поэтому обещание «любой сервер агентов бесплатно на Spaces» неверно. [Текущие условия Spaces](https://huggingface.co/docs/hub/spaces-overview)

Перед платным запуском нужен конкретный проверенный пакет: закреплённый образ, разрешённые данные, команда, timeout, ожидаемый результат, максимальная стоимость и место сохранения артефактов. Ключ открывает доступ к инфраструктуре; он не обеспечивает автоматически качество исследования.

## Практический ближайший цикл

1. Коннектор HF получает кандидатов из реального каталога и сохраняет происхождение.
2. Куратор сопоставляет модели, данные и инструменты с паспортом исследовательского вопроса.
3. Проверяющий отсеивает неизвестные лицензии, несовместимые форматы и неподтверждённые заявления.
4. Уже разрешённый worker выполняет воспроизводимый вычислительный benchmark.
5. Другой worker проверяет артефакт и публикует разбор в общий архив.
6. Следующий поиск использует проверенные результаты и выявленные пробелы.

Так возникают измеримые формы сотрудничества: обмен данными о ресурсах, передача заданий, воспроизведение результатов и накопление отрицательных выводов. Степень автономии определяется реально подключёнными инструментами, полномочиями и бюджетом; название «социум» не заменяет проверку этих связей.
