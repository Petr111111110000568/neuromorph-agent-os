# Учётные записи и способы доступа · v0.5

Модуль `workbench/network/accounts.py` ведёт постоянный реестр конфигураций провайдеров и запросов подключения. Данные сохраняются в отдельной SQLite; повторы одной пары `provider + reason` возвращают прежнюю запись. Сохранение профиля или заявки не создаёт внешнюю учётную запись, не выдаёт права и не устанавливает научный адаптер.

## Работающие публичные источники

Для реализованного поиска метаданных регистрация не требуется:

| Провайдер | Доступ в этой версии | Проверка |
|---|---|---|
| Europe PMC | Публичный REST поиск; профиль `europepmc`, `auth_mode=none`, `metadata:read` | Контрольный запрос без авторизации получил HTTP 200 и одну запись. [Проверенный endpoint](https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=epigenetics&format=json&pageSize=1). |
| Crossref | Публичный REST поиск; профиль `crossref`, `auth_mode=none`, `metadata:read` | Официальная документация прямо допускает доступ без регистрации и идентификации. [Access and authentication](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/). |

Проверка Europe PMC выполнена 18 сентября 2026 года; для запроса `epigenetics` получен `hitCount=129867`, возвращена одна запись. Это наблюдение доступности конкретного запроса, не обещание непрерывной доступности. [Страница документации Europe PMC](https://europepmc.org/RestfulWebService) в инструменте просмотра вернула 403, хотя запрос к API из Python завершился успешно.

У Crossref есть отдельные режимы: polite с контактным `mailto` и платный Metadata Plus. Текущий публичный путь не требует ни подписки, ни API-ключа. Адрес пользователя не выдумывается и не отправляется автоматически. Не следует переносить правила чтения метаданных на внесение изменений или публикацию данных. Требования и квоты необходимо проверять по текущей документации провайдера.

## Контракт данных

`POST /api/accounts` принимает только следующие поля:

```json
{
  "provider": "research_cloud",
  "domain": "research.example.org",
  "auth_mode": "api_key",
  "credential_env": "META_RESEARCH_CREDENTIAL",
  "scopes": ["models:read"],
  "setup_url": "https://research.example.org/settings"
}
```

Это пример структуры с зарезервированным демонстрационным доменом, а не доступный установленный сервис. Поддерживаются `none`, `api_key`, `oauth`, `manual`. В `credential_env` передаётся только имя серверной переменной окружения. В режиме `oauth` это также лишь ссылка на внешнее управление секретом: OAuth-вход, обновление токена и удалённая проверка в этом модуле не реализованы. `scopes` описывает намерение; права этим полем не предоставляются.

Возвращаются профиль, `created_at`, `updated_at`, `credential_present`, `remote_auth_verified` и вычисляемый `status`:

| Статус | Значение |
|---|---|
| `public_metadata_access` | Известный публичный профиль для чтения метаданных; сеть проверяется отдельным поиском. |
| `access_unverified` | Пользователь указал `none` для другого сервиса; свободный доступ не подтверждён. |
| `credential_present_unverified` | Непустая серверная переменная существует; удалённая авторизация не проверена. |
| `requires_setup` | Нужна настройка выбранного способа доступа. |

В этой версии `remote_auth_verified` всегда `false`. Наличие переменной проверяется при чтении; её значение не сохраняется, не возвращается и не добавляется в экспорт. Статус нельзя произвольно прислать клиентом.

Домен должен быть DNS-именем без схемы, пути, порта и учётных данных. `setup_url` разрешает HTTPS на точном имени хоста профиля; логин, пароль, query-параметры и fragment запрещены, чтобы не сохранять токены из ссылок авторизации. Неизвестные поля, включая `api_key`, `token`, `password`, отклоняются. Проверяются типы, длины и распространённые шаблоны случайно вставленных секретов. Это не заменяет правило пользователя не помещать секреты в свободный текст.

## Запрос подключения

```json
{"provider":"europepmc","reason":"Поиск метаданных для текущей кампании"}
```

`POST /api/accounts/request` сохраняет:

- `no_registration_required` для известных публичных профилей чтения метаданных;
- `requires_user_action` для остальных профилей: требуется существующая идентичность пользователя либо настройка на стороне конкретного сервиса.

Запись содержит официальную ссылку из профиля, время, причину и `external_action_performed=false`. Это журнал передачи настройки, а не утверждение об успешной регистрации. Историческая заявка неизменна даже после редактирования профиля и не служит разрешением на действие; актуальный режим определяется профилем и конкретным адаптером.

В текущем поручении разрешена оркестрация подключений, однако не указаны конкретная внешняя идентичность, адрес для регистрации, способ оплаты или поддерживаемый провайдером API создания аккаунта. Поэтому модуль делает всю доступную подготовку и сохраняет адресные задачи подключения. Он не подставляет вымышленные данные, не обходит CAPTCHA и не принимает за пользователя неизвестные условия сервиса.

## Расширение автоматической оркестрации

Следующий провайдер подключается отдельным адаптером с проверенным контрактом: разрешённые домены и операции, способ получения разрешённых credentials, минимальные scopes, обработка истечения токена, квоты, запись фактического результата. Если сервис предоставляет API автоматического создания рабочих пространств или сервисных аккаунтов и необходимые полномочия уже выданы пользователем, адаптер сможет выполнить конкретную разрешённую операцию. Общего автоматического регистратора для произвольных сайтов в v0.5 нет.

Секреты распределённого worker передаются через окружение или менеджер секретов непосредственно этому worker. Профили учётных записей не экспортируют и не рассылают секреты узлам. Для авторизации к coordinator используется отдельный `META_HUB_TOKEN`, описанный в документации транспорта.

## Проверки модуля

Восемь тестов проверяют публичные профили, отсутствие мнимой авторизации, сохранение после перезапуска, идемпотентность двух экземпляров coordinator, отсутствие значения секрета в SQLite и экспортируемых данных, динамическую проверку окружения, отклонение credential-полей и ложного статуса, привязку setup URL к хосту и различие чтения/записи метаданных.

```bash
python3 -m unittest discover -s tests -p test_accounts.py -v
```
