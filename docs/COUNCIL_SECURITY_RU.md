# Ограниченный совет логических ролей

`workbench/autonomy/council.py` задаёт проверяемые переходы состояния совета. Это чистый модуль стандартной библиотеки: он не обращается к сети и диску, не запускает код, не создаёт аккаунты, ключи или процессы и не устанавливает плагины. Хранение и модельные вызовы выполняет доверенный облачный контроллер.

Изначальные участники — `author`, `reviewer`, `reviser`. Все роли используют один существующий адаптер `qwen-official-space`: Qwen/Qwen3-Demo, revision `60e1db0778067d36b8a2793c350bf85cd461a298`, модельный alias `qwen3-235b-a22b`. Новый участник — дополнительная логическая специализация этой же модели. Это не новый внешний сервис и не независимая модель. Доступность Space и научная правильность результата голосованием не устанавливаются.

## Решения и ограничения

Поддерживаются предложения `meeting`, `create_member`, `admit_member`. Каждое содержит вопрос, обоснование и свидетельства по пяти категориям: `secrets`, `access`, `supply_chain`, `generated_code`, `resources`. Для каждой требуется объект `{ "passed": true, "evidence": "краткое свидетельство" }`. Отсутствие проверки, отрицательный флаг или пустое свидетельство отклоняет действие. Эти декларации модели не заменяют проверку доступа, закреплённых версий и ресурсов доверенным контроллером.

Для принятия нужны два голоса разных участников, существовавших при подаче предложения. Автор не голосует за своё предложение. Повторный голос не учитывается; отрицательный голос закрывает предложение. Предложение действует семь суток. Допускается не более четырёх одновременно ожидающих предложений, шести участников и одного нового участника за любые 24 часа. Второй голос во время ограничения частоты не расходуется: его можно повторно подать после разрешённого времени. Новые участники не получают право голосовать по более ранним предложениям.

Вопрос и причина ограничены 500 символами каждый, специализация — 240, свидетельство — 120. Идентификаторы имеют вид `[a-z][a-z0-9_]{0,31}`. Хранятся не более восьми последних переходов; весь документ состояния ограничен 32 KiB. Защита от повторной подачи охватывает текущие предложения, сохранённые восемь переходов и предложения уже принятых участников. Для бессрочной дедупликации контроллер использует внешнюю историю Git и уникальные идентификаторы запуска.

`create_member` и `admit_member` принимают только закреплённый адаптер. Внешний URL или имя иного провайдера возвращает `unsupported_adapter`; голосование не даёт доступ к этому сервису. В схеме нет команд изменения тарифа, лимитов, топологии доступа, установки расширений или отключения защиты. Глобальные лимиты облачного цикла остаются прежними; совет не резервирует дополнительные модельные вызовы.

## Контракт интеграции

```python
from workbench.autonomy import council

state = council.initial_state()  # или проверенное сохранённое состояние
council.validate_state(state)   # псевдоним check_schema
role_ids = council.members(state)
updated, receipt = council.apply_action(state, current_role, action, now_unix_seconds)
```

Действие предложения: `{ "operation": "propose", "proposal": { "id": "...", "kind": "meeting", "expected_revision": 0, "question": "...", "reason": "...", "security": { ... } } }`. Для создания или допуска роли добавляются `member_id`, `focus`, `adapter`. Действие голоса: `{ "operation": "vote", "proposal_id": "...", "decision": "approve", "expected_revision": 1 }`; также допустимо решение `reject`.

Прямые функции `receive_proposal(state, actor, proposal, now)` и `vote(state, actor, proposal_id, decision, now, expected_revision=...)` возвращают `(updated, receipt)`. Они поднимают `ValueError` при некорректном действии. `apply_action` сохраняет прежнее состояние и возвращает обезличенный `rejected` для некорректного модельного действия; повреждённое сохранённое состояние всегда вызывает ошибку. Входное состояние не изменяется.

Ревизия предотвращает применение устаревшего предложения в памяти. Реальную защиту от параллельной записи должен обеспечивать атомарный Git CAS контроллера; чистый модуль сам не является распределённой блокировкой. Модель передаёт только отдельное действие, а не полный JSON состояния. Доверенный контроллер обязан проверять фактическую личность выполняющейся роли, сопоставлять адаптер с закреплённым контрактом и не выдавать модели токен публикации.

Одобрение собрания фиксирует решение обсудить вопрос. Самостоятельный запуск будущего обсуждения, выбор очередной роли и включение контекста в следующий существующий облачный вызов обеспечиваются контроллером, а не этим модулем. Созданные материалы остаются непроверенными предложениями до соответствующих проверок.

Тесты в `tests/test_council.py` предназначены для GitHub Actions/Colab. Локально код и тесты при этой реализации не запускались; факт успешной облачной проверки следует фиксировать по результату CI.
