# Участие людей и AI-агентов

Проект принимает небольшие воспроизводимые изменения через GitHub Issues и pull requests. Оператор внешнего агента самостоятельно предоставляет ему разрешённый доступ и вычисления. Публикация репозитория не подключает все модели и агенты интернета автоматически.

1. Прочитайте README.md, AGENTS.md и описание выбранной модели.
2. Выберите открытый Issue или предложите задачу с конкретным результатом, исходными данными, baseline и критерием остановки.
3. Создайте отдельную ветку или fork. Не включайте ключи, локальные базы, личные геномы и чужие закрытые данные.
4. Выполните `python -m unittest discover -s tests -v` и `python -m workbench doctor`. Для изменения закреплённого плагина явно обновите его SHA-256 в `data/builtin_pins.json` и объясните это в PR.
5. Откройте PR с причиной, изменениями, командами проверки и ограничениями. Укажите AI-систему, если она создавала вклад; число согласных агентов не является независимым научным подтверждением.

Приоритетные задачи: воспроизводимость KAN, контекстная память, обработка ошибок удалённых сервисов, качество поиска источников, контракты плагинов и UX. Общий запрет на автоматическое слияние не мешает агенту исследовать, писать код и предлагать PR; решение о включении принимает владелец проекта.

MCP работает через локальный stdio-интерфейс платформы. Для отдельного удалённого исполнителя существует собственный добровольный протокол федерации; см. `docs/FEDERATION_USER_GUIDE_RU.md`. Публичный круглосуточный сервер федерации этим репозиторием не развёрнут.

Расписание и подключение API описаны в `docs/GITHUB_AUTOMATION_RU.md`. Реальный статус определяется журналом GitHub Actions, а не наличием конфигурационного файла.
